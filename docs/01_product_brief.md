# 01. 제품 기획

설계 v0.4 · 2026-10-30 · 개발 착수

## 제품 정의

네 손가락으로 캐릭터의 네 팔다리를 직접 옮기면서, 발판과 손잡이의 순서를 읽고 벽을 오르는 모바일 클라이밍 게임이다. 재미의 중심은 작은 움직임을 연결해 어려운 자세를 해결하는 성취감이다. 단순 연타, 캐릭터 능력치 성장, 무작위 추락을 핵심 재미로 삼지 않는다.

작업명은 Climb Game이다. 정식 이름·브랜드는 미정이다. 화면의 왼쪽/오른쪽과 캐릭터의 해부학적 왼쪽/오른쪽이 일치하도록 캐릭터의 등을 보는 카메라를 사용한다.

## 대상과 사용 상황

- 짧게 반복하면서 조작을 익히는 물리·퍼즐 게임 사용자.
- 1회 플레이 목표 2~5분, 일반 루트의 처음 플레이 목표 45~180초. 숙련도에 따라 달라지는 목표값이다.
- 기본 자세: 책상·무릎·거치대에 휴대폰을 안정적으로 놓고 양손의 두 손가락 사용.
- 손에 들고 네 손가락을 사용하는 자세는 별도 평가한다. 휴대폰을 쥔 채 편하게 된다고 가정하지 않는다.
- 네 손가락 동시 입력은 지원하지만 매 순간 네 개를 누르도록 강제하지 않는다.

## 경험 원칙

| 원칙 | 실제 게임의 행동 |
| --- | --- |
| 조작의 예측 가능성 | 조작을 시작한 영역의 팔다리는 손가락이 다른 영역으로 가도 바뀌지 않는다 |
| 실패 원인의 가시성 | 거리 초과·체력 소진·지지 상실을 서로 다른 표시로 설명한다 |
| 발을 쓰는 가치 | 발을 높여 지지하면 몸통이 올라가고 팔 피로가 줄어든다 |
| 관찰할 여유 | 잡고 있는 동안 손가락을 떼고 다음 움직임을 생각할 수 있다 |
| 짧은 복구 | 실패 후 같은 루트를 빠르게 다시 시도한다 |
| 아트와 가독성의 양립 | 예쁜 벽 재질보다 손발·홀드·연결 상태가 먼저 읽힌다 |

## MVP 범위

| 영역 | 포함 | 이후 검토 |
| --- | --- | --- |
| 조작 | 네 팔다리 독립 드래그, 4점 동시 입력, 패드 크기·위치 조정 | 대체 컨트롤러, 한 손 모드 |
| 캐릭터 | 1종, 고정 체형·도달 거리, 팔·다리 IK | 다른 체형, 고급 옷 물리 |
| 게임 | 홀드·발판·피로·추락·완등, 연습 보조 | 점프, 다이노, 매달린 채 스윙 점프 |
| 콘텐츠 | 튜토리얼 3개 + 일반 루트 9개, 실내 벽 1테마 | 야외 암벽, 움직이는 홀드, 절차 생성 |
| 기록 | 로컬 진행·메달·최고기록, 재시도 | 온라인 랭킹, 리플레이 공유 |
| 연출 | 기본 손발 접촉, 흔들림, 효과음·진동 | 음성, 대규모 시네마틱 |
| 운영 | 오프라인, 설정 저장 | 계정·동기화·멀티플레이·광고·결제 |

MVP의 외형 변형은 같은 캐릭터의 무료 색상 3개다. 능력치 차이와 장비 강화는 없다. 스테이지 개수보다 조작 검증이 우선이며, G1/G2 검증 실패 시 콘텐츠 제작은 보류한다.

## 성공 기준과 출시 판단

아래는 초기 내부 검증 목표다. 실제 성과나 시장 지표가 아니다. 5~8명 테스트는 방향 판단에 사용하고 통계적 시장 검증으로 확대 해석하지 않는다.

| 기준 | 내부 통과 목표 | 확인 방법 |
| --- | --- | --- |
| 첫 조작 이해 | 처음 하는 사람의 80% 이상이 3분 내 T01 완료 | 진행자 설명 없이 관찰 |
| 팔다리 식별 | 의도한 팔다리와 실제 팔다리 불일치 5% 미만 | 1인 40회 의도 확인 과제 |
| 편안함 | 10분 후 불편도 중앙값 3/10 이하 | 크기가 다른 휴대폰, 자세별 조사 |
| 네 손가락 안정성 | 지정 순서 100세트에서 잘못된 재배정 0건 | 실제 기기 입력 로그 비교 |
| 실패 이해 | 실패 직후 원인 설명 일치 80% 이상 | 원인 표시와 플레이어 응답 비교 |
| 재미 방향 | 테스트 참여자 60% 이상이 자발적 재시도 | 종료 선택을 강제하지 않고 관찰 |
| 플레이 성능 | 지정 목표 기기에서 60FPS 기준 검증 | [검증 계획](10_validation.md) 참고 |

## 제품 운영과 확장 원칙

초기 제품은 설치 후 바로 플레이하도록 한다. 로그인·네트워크가 첫 화면을 막지 않는다. 분석은 로컬 디버그 기록만 사용한다. 외부 분석·광고 SDK는 필요성과 개인정보 처리 범위를 별도 설계한 후 추가한다.

상용화는 핵심 조작과 콘텐츠 만족도를 확인한 뒤 유료 구매 또는 추가 루트 팩 등을 비교한다. 이번 계획에는 가격·매출·결제 연동을 확정하지 않는다. 업데이트 우선순위는 조작 오류, 추락 판정, 세이브 안정성, 신규 콘텐츠 순서다.
