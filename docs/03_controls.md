# 03. 네 손가락 조작 명세

이 문서의 필수 조건은 네 팔다리 독립 조작이다. 두 엄지로 팔다리를 순차 조작하는 것은 가능한 이용 방식일 뿐, 네 손가락 입력을 대체하는 구현안이 아니다.

## 영역과 손가락

| 화면 영역 | 소유 팔다리 | 표기 |
| --- | --- | --- |
| 왼쪽 위 패드 | 왼손 | LH / 손 아이콘 |
| 왼쪽 아래 패드 | 왼발 | LF / 발 아이콘 |
| 오른쪽 위 패드 | 오른손 | RH / 손 아이콘 |
| 오른쪽 아래 패드 | 오른발 | RF / 발 아이콘 |

캐릭터는 등을 보여 화면 좌우와 신체 좌우가 같다. 어느 손가락으로 눌러도 영역이 담당 팔다리를 정한다. 검지·중지 등 해부학적 손가락은 장치가 식별한다고 가정하지 않는다. 왼손의 두 손가락을 왼쪽에, 오른손의 두 손가락을 오른쪽에 편하게 놓도록 패드 위치를 조정한다.

## 조작 모델: 상대 이동 트랙패드

패드의 누른 위치 자체가 캐릭터 손발 위치는 아니다. 터치를 시작한 뒤 움직인 거리와 방향을 해당 말단의 목표 이동량으로 쓴다. 손가락이 중앙의 캐릭터나 홀드를 가리지 않도록 간접 조작한다. 조이스틱처럼 누르고 있는 방향으로 계속 이동하지 않으며, 손가락이 멈추면 목표도 멈춘다.

화면 드래그의 위쪽은 벽면 위쪽, 오른쪽은 벽면 오른쪽이다. 이동량은 콘텐츠 스케일이 적용되지 않은 화면 이동량을 기준으로 패드 크기와 사용자 감도를 반영해 월드 단위로 변환한다. Godot의 `screen_relative`와 `relative`를 혼용하거나 해상도 배율을 두 번 곱하지 않는다. 실제 API 근거는 [공식 근거](13_references.md)의 S02·S03을 따른다.

패드 지름만큼 움직이면 기본적으로 월드 1.0m를 목표 이동량으로 요청한다. 감도는 0.6~1.6배 설정한다. 최초 말단 위치에서 이동량을 누적하며 고정 패드 중심으로 강제 복귀시키지 않는다. 매 입력 후 요청 목표를 현재 도달 영역에 제한해 초과 누적량을 버린다. 실제 말단은 별도의 이동 속도 제한으로 이 목표를 따라온다. 손가락을 반대로 움직이면 즉시 요청 목표도 돌아와야 한다.

### 좌표 변환과 선택 영역

안전영역의 실제 픽셀 크기를 W/H, 균일 UI 배율을 k=min(W/1600, H/900), 저장된 패드 지름을 D라 한다. 초기 D=160 논리 단위이며 실제 패드 지름은 D×k 픽셀이다. 이벤트의 화면 이동량 (dx,dy)을 월드 이동량 (dx,-dy)×감도/(D×k)로 변환한다. 패드 지름의 기준 이동 거리는 1.0m다. 화면 해상도 배율·카메라 줌을 다시 곱하지 않는다.

데드존 비교에는 시작점부터 현재 손가락까지의 직선 거리를 k로 나눈 논리 거리를 쓴다. 떨림의 이동 경로 길이를 합산하지 않는다. 최초로 데드존을 넘은 이벤트에서는 직선 벡터에서 데드존 길이를 제외한 초과분만 적용한다. 이후에는 개별 이동량을 적용한다. 한 번 Dragging이 되면 시작점으로 돌아와도 ArmedAttached로 되돌아가지 않는다.

패드의 원형 히트영역은 표시 지름과 동일하고 가장자리를 포함한다. 패드 사이에 숨겨진 겹치는 영역을 만들지 않는다. 영역 밖에서 시작한 터치는 들어와도 배정하지 않는다. 현재 패드 크기·배율·감도는 터치 시작 시 고정하며 변경하려면 일시정지 후 입력을 초기화한다. 위치·크기 제약은 [05](05_screens_and_ux.md)에 따른다.

## 입력 소유권 계약

| 상황 | 처리 |
| --- | --- |
| 패드에서 새 터치 시작 | 해당 팔다리가 비어 있으면 터치 ID를 전용 배정 |
| 입력 순서 변경 | 먼저 누른 손가락이 왼손이라는 가정 금지 |
| 영역을 넘어 드래그 | 터치 종료까지 원래 팔다리 유지 |
| 같은 패드의 두 번째 터치 | 무시. 기존 터치를 빼앗거나 교체하지 않음 |
| 중앙에서 시작한 터치 | 게임 말단에 배정하지 않음. 패드로 이동해도 배정하지 않음 |
| 다섯 번째 터치 | 현재 팔다리 소유권에 영향 없음. 배정되지 않은 UI 터치만 처리 가능 |
| 네 손가락이 교차 | 손가락의 좌우 순서를 재정렬하지 않음 |
| 일부 손가락만 뗌 | 그 ID만 종료, 다른 팔다리 계속 조작 |
| 종료된 ID 재사용 | 이전 소유권 제거 후 새 세션으로 취급 |
| 터치에서 생성된 마우스 이벤트 | 모바일에서는 중복 입력 경로로 처리하지 않음 |

터치 ID를 0~3으로 가정하지 않는다. 최대 활성 팔다리가 네 개일 뿐이며, 장치의 터치 식별자 값은 별개다. `(입력 세션 세대, 터치 ID)`로 늦게 도착한 이벤트와 재개 이후의 새 입력을 구분한다.

## 팔다리 상태

| 상태 | 의미 | 주요 전이 |
| --- | --- | --- |
| Attached | 슬롯에 붙어 있음, 활성 터치 없음 | 패드 누름 → ArmedAttached |
| ArmedAttached | 선택되었지만 기존 접점 유지 | 데드존 넘음 → Dragging / 정상 종료 → Attached |
| Dragging | 접점 해제, 말단 목표를 조작 | 정상 종료·후보 유효 → Attached / 실패 → Free |
| Free | 잡지 않은 손발 | 패드 누름 → Dragging |

슬롯 후보는 Dragging의 부가 표시다. 후보 표시만으로 Attached가 되지 않는다. 다른 손발의 이동으로 후보가 무효화되면 놓는 순간 잡기를 거부한다.

데드존은 논리 좌표 10단위를 초기값으로 삼되 손 크기·해상도별 조정값이다. 실제 물리 길이로 확정한 값이 아니며 10px로 직접 쓰지 않는다. 데드존을 넘을 때 초과 이동분부터 적용해 시작 순간 튀는 현상을 막는다.

## 후보 선택과 동시 잡기

1. 현재 말단의 도달 가능 범위 안에서 말단 종류가 허용된 슬롯을 찾는다.
2. 판정상 말단과 슬롯 간 거리가 후보 반경 이하인지 확인한다. 손가락의 먼 요청 목표를 잡기 위치로 사용하지 않는다.
3. 비어 있는 슬롯을 거리 우선으로 고르고, 현재 후보보다 0.03m 이상 가까운 새 후보가 있을 때 전환한다. 현재 후보가 무효이면 즉시 제거한다.
4. 정상 release에 기록된 후보를 물리 틱에서 재검사한다. 마지막으로 제시한 후보가 무효가 되었으면 다른 슬롯을 몰래 선택하지 않고 거부한다. 아직 후보를 표시한 적이 없는 짧은 제스처는 release를 처리하는 판정상 말단 위치에서 후보를 구한다.
5. 같은 틱의 다중 요청은 일괄 평가하고 함께 가능한 조합만 확정한다.

동일 슬롯 충돌 시 기존 점유자가 우선한다. 새 요청끼리는 거리, 접수 순번, 마지막으로 고정 limb ID 순으로 우선순위를 결정한다. 동시에 한 손이 나가고 다른 손이 들어오는 교체는 같은 틱의 분리 처리를 먼저 반영한다. 정상 홀드의 두 손 슬롯은 별개이므로 양손 동시 완료가 가능하다.

말단이 아직 요청 목표까지 움직이지 못했다면 release 후 계속 날아가 잡아주지 않는다. 그 순간 판정상 말단에서 후보를 검사해 성공/거부를 결정한다. 한 틱에 입력이 몰리거나 같은 팔다리를 다시 누르는 순서는 [15. 실행 규칙](15_runtime_contract.md)에서 정한다.

### 후보와 잡기 거부 사유

| 사유 ID | 판정 | 화면 처리 |
| --- | --- | --- |
| NO_TARGET | 후보 반경 안에 허용 슬롯 없음 | 잠깐의 빈 링, 과도한 실패음 없음 |
| TYPE_MISMATCH | 해당 손/발이 허용되지 않음 | 손/발 아이콘 차이 표시 |
| OCCUPIED | 기존 팔다리 또는 같은 배치의 우선 요청이 점유 | 점유 표식 |
| OUT_OF_REACH | 현재 몸통에서 슬롯까지 거리·관절 조건 불만족 | 도달 경계 |
| BLOCKED_PATH | 말단과 슬롯 사이 또는 접촉 자세에 장애물 | 가림 표시 |
| POSE_CONFLICT | 기존 접점과 함께 성립할 수 없는 자세 | 몸통을 옮기라는 안내 |
| STALE_CANDIDATE | 보여준 후보가 release 시점에 무효 | 후보 링 제거, 임의 대체 없음 |
| WRONG_PHASE | 추락·결과 등 잡기 불가 상태 | 게임 잡기 피드백 없이 입력 무시 |

사용자에게 매번 사유 ID를 보여주지는 않는다. UI는 한 가지 우선 원인만 보여주고 진단 로그에는 전체 판정을 남긴다. 소유권이 없는 잡기 요청은 정상 게임 실패 통계에 넣지 않는다.

## 손가락 재배치와 잘못 놓기

Attached에서는 손가락을 언제든 떼고 다시 놓을 수 있다. Dragging에서 손가락을 떼면 항상 잡기 시도가 발생한다. 재배치만을 위해 공중에서 떼었더라도 도달 가능한 후보가 없으면 Free가 된다. 이 차이는 첫 튜토리얼에서 직접 경험하게 한다. 자동 원위치 복귀, 숨겨진 추가 버튼, 더블탭 분리 규칙은 MVP에 넣지 않는다.

## 앱 중단과 UI 충돌

- 취소 이벤트, 포커스 상실, 앱 백그라운드 진입, 화면 크기·안전영역 변경은 시스템 중단으로 본다.
- 중단 즉시 시간·피로·물리를 멈추고 모든 터치 소유권을 지운다. 취소를 정상 release로 전달하지 않는다.
- 이미 Attached인 접점은 보존한다. 드래그 중이던 팔다리는 그 위치의 Free 상태로 보존한다. 사라진 접점을 만들어 붙이지 않는다.
- 재개 버튼을 누르고 해당 UI 터치를 끝내면 Paused 안에서 3초 준비 카운트를 시작한다. 이 동안 Free 팔다리의 패드에 새 터치를 배정할 수 있다. 준비 단계에서는 목표 이동이나 잡기 판정을 하지 않고, 떼어진 터치는 소유권만 제거한다. 다섯 번째 손가락으로 재개 버튼을 누를 필요가 없도록 한다.
- 재개 시 현재 화면의 손가락 위치를 새 기준점으로 삼고, 중단 전 드래그 이동량을 재생하지 않는다. 지원이 없는 위험 상태는 재개해도 안전 상태로 바뀌지 않는다.
- 일시정지 버튼은 중앙 상단에 둔다. 패드에서 시작한 터치가 버튼을 지나도 클릭하지 않는다.
- 설정창과 결과창이 열릴 때 입력 세대를 증가시키고 오래된 터치 이벤트를 버린다. 창을 닫아도 게임으로 터치가 통과하지 않는다.

## 카메라와 입력

MVP 카메라는 회전·핀치 줌을 지원하지 않고 상하 추적만 한다. 말단 목표는 월드 좌표로 유지하고 입력 이동량을 고정 벽면 축에 적용한다. 따라서 카메라가 올라가도 정지한 손가락 때문에 말단이 움직이지 않는다. 화면의 후보 표시는 매 렌더 프레임 월드 좌표를 투영해 그린다.

## 실제 기기 검증 과제

네 개 순차 누름, 네 개 동시 누름, 두 개 이동 중 나머지 두 개 누름, 같은 프레임 놓기, 교차, 손가락 재누름, 다섯 번째 터치, 시스템 제스처, 알림·전화 중단, 카메라 스크롤, 패드 가장자리, 60/120Hz 화면을 검증한다. 에디터의 마우스 조작은 동작 디버깅만 가능하며 네 손가락 사용성을 검증한 것으로 보지 않는다.
