# 04. 자세·물리·IK 설계

이 문서는 수치의 단일 기준이다. 아래 값은 모두 최초 프로토타입의 조정용 초깃값이며, 실측·생체역학 수치 또는 구현 완료 값이 아니다.

## 채택 구조

**게임 판정용 2D 자세 상태 + 제약된 몸통 운동 + 3D 스켈레톤 표현**을 제안한다. 보이는 캐릭터는 3D이고, 손발·몸통의 판정은 벽면 위 X/Y에서 수행한다. Z는 벽으로부터의 시각적 거리와 겹침 해소에만 사용한다. 손발을 홀드에 고정한 채 골반 위치와 몸통 기울기를 조정하고, 팔꿈치·무릎은 두 관절 IK로 연결한다.

| 방식 | 장점 | 부담 | 선택 |
| --- | --- | --- | --- |
| 전신 자유 래그돌 | 자연스러운 낙하·흔들림 | 떨림, 관절 폭주, 기기별 안정성 조정 | 기본 조작에는 사용하지 않음 |
| 애니메이션만 재생 | 예측·제어 쉬움 | 임의 홀드 배치와 독립 손발 조작에 부족 | 접촉·표정 보조에만 사용 |
| 제약 기반 자세 + IK | 네 말단 목표·접점을 직접 관리 | 몸통 이동과 제약 해결을 설계해야 함 | MVP 기본안 |

이는 사실적인 스포츠 시뮬레이션이 아니다. 단순화한 지지·피로 규칙으로 일관된 조작 경험을 만든다. 엔진 강체와 별도 자세 계산이 동시에 같은 몸통 위치를 쓰지 않게 한다.

## 좌표·크기 계약

월드 단위 1=1m로 작성한다. X는 오른쪽, Y는 위쪽, Z는 벽 바깥쪽이다. 루트 원점은 해당 벽 바닥 중앙이다. 모델 원점은 골반이다. 뼈와 슬롯은 명시한 로컬/월드 좌표를 변환해 사용하며 Skeleton3D의 스켈레톤 상대 global pose를 월드 좌표로 오해하지 않는다(S06).

| 항목 | 초기값 | 의미 |
| --- | --- | --- |
| 팔 위/아래 길이 | 0.40 / 0.38m | 총 0.78m, 좌우 동일 |
| 다리 위/아래 길이 | 0.52 / 0.48m | 총 1.00m, 좌우 동일 |
| 어깨 위치 | 골반 기준 X ±0.20, Y +0.55m | 기본 자세, 몸통 회전 반영 |
| 고관절 위치 | 골반 기준 X ±0.14, Y 0m | 몸통/골반 회전 반영 |
| 팔 도달 거리 | 0.20~0.78m | 어깨부터 손까지 |
| 다리 도달 거리 | 0.25~1.00m | 고관절부터 발까지 |
| 선호 팔/다리 거리 | 0.52 / 0.78m | 고정 길이가 아닌 자세 비용의 기준 |
| 몸통 회전 | 벽면에서 -25°~+25° | 극단적인 뒤집힘 방지 |
| 관절 각도 | 팔꿈치 굽힘 5°~155°, 무릎 5°~145° | 완전 펴짐=0°. 실제 허용 거리와 교집합 적용 |

도달 거리 최대값만 만족해도 관절 제한에 걸릴 수 있다. 유효성은 거리·관절·충돌을 함께 검사한다. 모델 비율 변경은 조작 범위·기존 루트 전체 재검증 대상이다. 옷과 색상은 판정 길이를 바꾸지 않는다.

## 몸통이 올라가는 원리

입력의 책임은 말단 목표를 만드는 데서 끝난다. 자세 계산기는 현재 고정된 손·발과 몸통 충돌 조건에서 가능한 골반 위치·회전을 찾는다.

1. 지지가 있는 동안에는 접점에 맞는 목표 자세와 제한된 자세 보정 운동을 계산한다. 이 모드에 중력 가속도를 중복 적용하지 않는다. 중력에 의한 자유 낙하는 Falling에서만 적용한다.
2. 고정된 손에는 팔 길이·관절·접점 조건을, 지지 중인 발에는 다리 길이·압축 지지 조건을 적용한다.
3. 후보 중 선호 팔/다리 굽힘, 과도한 몸통 회전, 접점 중심에서의 좌우 이탈 비용이 작은 자세를 선택한다. 같은 비용이면 이전 자세와 가까운 것을 선택한다.
4. 새 목표로 속도 제한을 두어 이동하고, 각 반복에서 고정 접점을 다시 만족시키도록 투영한다.
5. 결과가 제약을 만족하는 경우에만 게임 상태로 확정한다.

목적함수는 선호 길이 오차 + 회전 비용 + 좌우 정렬 비용이다. 가중치는 아래 계산 계약과 조정표로 정한다. Y를 계속 높이는 보너스나 화면 위쪽으로 밀어주는 상시 상승력은 넣지 않는다. 접점이 그대로라면 목표 자세가 수렴하여 더 이상 올라가지 않아야 한다. 이전 자세에 대한 큰 이동은 목적함수의 누적 편향 대신 속도·가속도 제한으로 억제한다.

높은 발을 디딘 뒤 다리를 편하게 펴는 자세를 찾으면 골반이 올라간다. 높은 손을 잡으면 팔이 너무 펴진 불편한 자세를 줄이면서 몸통이 당겨진다. 모든 기존 접점과 충돌을 유지할 수 없으면 그 새 접점을 잡지 못한다. 이 원리가 재미있게 작동하는지는 G2 검증의 핵심이며 설계만으로 보장할 수 없다.

## 지지 모델

벽 위에서는 적어도 한 손이 고정되어 있어야 지지가 성립한다. 양발만으로 매달리는 것은 허용하지 않는다. 별도로 지정한 시작/휴식 플랫폼에서는 바닥 지지로 서 있을 수 있다.

손 접점은 매달림 지지를, 발 접점은 위로 받치는 압축 지지를 제공한다. 발판에는 벽면 내 지지 방향과 허용 각도 범위를 둔다. 그 방향으로 체중을 싣지 못하는 자세의 발은 시각적으로 가까워도 유효 지지 발로 세지 않는다. 발이 골반보다 높아서 발에 매달리는 형태는 지지에서 제외한다. 실제 접촉력 최적화의 완전한 해를 요구하지 않고, 지원 방향·상대 위치·제약 만족 여부로 분류한다.

지지 발 개수는 피로 분류에도 사용한다. 슬롯에 붙었다는 사실과 실제로 지지 중이라는 사실은 별도다. 발이 지지를 잃으면 HUD에서 이를 보여주고 피로를 다시 계산한다.

### 지지 판정의 구체 조건

일반 발판의 지지 방향은 월드 위쪽 (0,1)이며 기본 허용 반각은 60°다. 슬롯에서 같은 쪽 고관절로 향하는 단위 벡터와 지지 방향의 내적이 cos(60°) 이상이고, 고관절이 슬롯보다 0.05m 이상 높고, 다리 길이·관절 조건이 유효하면 지지 발이다. 방향이 없는 상태나 길이 0 벡터는 지지로 보지 않는다. 방향·높이 문턱에는 각각 5°·0.01m의 종료 히스테리시스를 둔다. 신규 지지는 원래 문턱을 통과해야 한다.

플랫폼 지지는 지정된 두 발 슬롯을 LF/RF가 나눠 점유하고, 골반 X가 두 발의 X 범위에 좌우 여유 0.10m를 더한 구간 안에 있으며, 두 발의 지지 조건과 몸통 충돌 조건이 유효할 때 성립한다. 플랫폼은 바닥 영역과 관련 발 슬롯 ID를 갖는다. 단순히 플랫폼 그림 위에 캐릭터가 겹친 상태는 지지가 아니다.

벽의 유효 손이 0이고 플랫폼 지지도 없으면 Climbing 내부의 Grace에 진입한다. Grace에서는 골반을 직전 위치에 유지하고 속도를 0으로 둔다. 말단 입력과 잡기, Free 손 회복은 계속 처리하지만 자동 몸통 상승과 성공 유지 카운트는 멈춘다. 9개의 연속 무지지 틱이 확정되면 Falling으로 전환한다. 유예 안의 재잡기는 추락이 시작된 뒤의 공중 재잡기와 다르다. 중단·재개 시 유예 카운트를 초기화하지 않는다.

## 자세 계산의 구현 계약

### 변수와 유효 영역

몸통 변수는 골반 X/Y와 벽면 회전 θ 세 개다. 이 후보에서 어깨·고관절을 변환하고 고정된 모든 말단의 거리·관절·충돌을 검사한다. 발이 현재 하중을 지지하지 않더라도 Attached 상태의 위치 제약은 유지한다. 지지하지 않는 발이 몸통에 맞지 않는다는 이유로 자동 분리되지 않는다.

두 뼈의 길이를 a,b, 완전 펴짐을 0°로 한 굽힘 각도를 φ라 하면 말단 거리의 제곱은 a²+b²+2ab cos(φ)다. 허용 거리는 이 식에서 얻는 범위와 위 좌표·크기 계약의 거리 범위의 교집합이다. 다리는 굽힘 145° 제한 때문에 약 0.303m보다 더 접을 수 없다. 단순히 명목 최솟값 0.25m만 사용하지 않는다.

기본 몸통 충돌 대리체는 골반에서 Y=0.10~0.48m의 선분에 반지름 0.18m를 더한 캡슐, 머리는 (0,0.78m)를 중심으로 반지름 0.13m인 원으로 시작한다. 둘 다 몸통 회전을 반영한다. 팔·다리·장식은 충돌 대리체에서 제외한다. 유효 공간 검사에서는 이 대리체와 벽면 장애물·바닥만 검사한다.

### 목표 자세 점수

각 거리는 m, θ는 도를 사용한다. d는 해당 관절에서 고정 슬롯까지 거리, c는 현재 고정 접점 X의 산술 평균이다. c는 빈 집합에 대해 계산하지 않는다. 지지가 없는 경우 목표 자세 계산 자체를 하지 않는다.

| 비용 항목 | 계산 | 초기 가중치 |
| --- | --- | --- |
| 손의 선호 굽힘 | 고정된 각 손의 ((d−0.52)/0.78)² 합 | 1.00 |
| 발의 선호 굽힘 | 지지 중인 각 발의 ((d−0.78)/1.00)² 합 | 1.25 |
| 몸통 기울기 | (θ/25)² | 0.20 |
| 접점 중심과 좌우 정렬 | ((골반 X−c)/1.00)² | 0.10 |

가중 합이 작을수록 편한 목표 자세로 본다. 이전 틱의 지지 발 집합을 한 번의 탐색 동안 고정하고, 최종 자세에서 지지 집합을 다시 평가한다. 집합이 바뀌면 다음 틱에 새 비용을 반영한다. 한 틱 안에서 지지 집합과 자세를 끝없이 번갈아 계산하지 않는다.

### 목표 탐색과 실제 이동

초기 해법은 3변수의 작은 근방 탐색이다. 현재 유효 자세를 시작점으로 X/Y에 각각 -0.04/0/+0.04m, θ에 -4/0/+4°를 적용한 27개 후보를 고정 순서로 평가한다. 유효 후보 중 비용이 가장 낮은 것을 고른다. 개선이 없으면 탐색 간격을 반으로 줄이며, 최대 8라운드까지만 수행한다. 틱 시작 위치에서 0.30m 또는 회전 15°보다 먼 탐색 후보는 제외한다. 비용 차이 0.00001 이하는 동률로 보고 이전 자세와 가까운 후보를 우선한다.

이 탐색 결과는 **목표 자세**이며 캐릭터를 즉시 이동시키는 위치가 아니다. 골반 보정 가속도는 목표와 현재 위치 차이의 40배에서 속도의 12배를 뺀 값을 시작점으로 하고, 크기 12m/s²·속도 1.2m/s 상한을 적용한다. 회전도 같은 형태의 보정을 사용하되 별도의 각도 이득·속도·가속도 상한을 적용한다. 실제 이동은 고정 틱 간격으로 적분한다.

제안된 다음 자세가 기존 접점이나 충돌 조건을 깨면 이동량을 1, 1/2, 1/4, 1/8, 1/16, 1/32, 0배 순으로 줄여 유효한 위치를 고른다. 장애물을 통과하지 않는지는 이동 구간의 충돌 검사로 확인한다. 최종 속도는 실제 이동한 거리를 틱 간격으로 나누어 계산한다. 한 번에 큰 위치 보정을 넣어 제약 오차를 감추지 않는다.

현재 자세가 유효하지만 더 나은 후보를 못 찾으면 정지 유지가 정상 결과다. 지역 최솟값 때문에 게임이 답답해지는지 G2에서 평가한다. 다른 해법으로 바꾸는 조건은 의도 경로에서 유효한 가까운 자세가 있는데 반복적으로 이동하지 못하거나 틱 예산을 넘는 경우다. 아직 이 계산을 구현하거나 성능을 검증하지 않았다.

### 잡기·Free 말단·이동 속도의 관계

새 슬롯은 현재 몸통 자세에서 도달 가능해야 한다. 슬롯을 잡기 위해 몸통을 순간 이동시키지 않는다. 현재 판정상 말단과 슬롯 사이가 후보 반경 안이면 접점 스냅을 허용하되, 그 짧은 이동 구간이 장애물을 통과하면 거부한다. 이 반경 내 접점 스냅만 endpoint_follow_speed의 예외다. 큰 요청 목표까지의 뒤늦은 자동 이동은 없다.

Free이며 터치가 없는 손의 휴식 목표는 골반 기준 (왼쪽 -0.30/오른쪽 +0.30, +0.18m), 발은 (왼쪽 -0.25/오른쪽 +0.25, -0.70m)다. 현재 도달 영역과 관절 조건으로 제한하고 말단 속도 상한 안에서 따라간다. 따라서 잡기 실패 후에는 손발이 자연스럽게 내려오며 이전 홀드로 돌아붙지 않는다. Paused에서는 이 움직임도 멈춘다.

## 한 물리 틱의 순서

1. 입력 명령 수집: 취소/일시정지를 가장 먼저 처리한다.
2. 기존 상태의 스냅숏에서 의도적인 분리와 드래그 목표를 적용한다.
3. 정상 release의 새 잡기 후보를 계산한다.
4. 기존 접점을 우선 보존하면서 새 요청 조합을 평가한다. 최대 네 요청이므로 가능한 조합을 제한적으로 비교할 수 있다.
5. 양립 가능한 새 접점만 틱 내부의 잠정 상태에 적용한다. 거부된 말단은 Free다. 아직 UI·저장에 성공 이벤트를 내보내지 않는다.
6. 몸통·말단 자세를 풀고, 지지 발과 피로를 갱신한다.
7. 피로가 0인 손을 분리하고 지지 상실 유예를 갱신한다.
8. 추락 여부를 판정한 뒤 정상 유지/체크포인트/기록을 갱신한다.
9. 틱의 유효성이 확인되면 상태와 이벤트를 함께 확정하고 렌더링·IK·사운드·저장에 전달한다. 정확한 순서는 [15](15_runtime_contract.md)를 따른다.

같은 틱에 두 손이 각각 가능한 홀드를 선택해도 두 접점의 조합이 불가능할 수 있다. 이때 개별 성공을 먼저 통보하지 않는다. 채택 조합은 신규 접점 수 최대 → 거리 합 최소 → 입력 순번 → 고정 limb ID로 고른다. 기존 슬롯 점유는 신규 요청보다 우선한다.

## IK와 표현

팔꿈치·무릎은 이전 프레임의 굽힘 방향과 리그의 pole 방향을 기준으로 계산해 관절이 갑자기 반대로 꺾이지 않게 한다. 도달 불가 목표는 가장 가까운 허용 위치로 제한하고 UI에 경계를 표시한다. 고정된 손발을 애니메이션이 끌어내지 못하도록 접촉 IK를 최종 우선으로 적용한다.

손가락은 붙기·떨어지기 포즈, 발은 발끝 접촉 각도, 몸통은 호흡·작은 흔들림만 추가한다. 화면 깊이 방향의 팔/다리 교차 보정은 시각 전용이며 도달 거리를 늘리지 않는다. MVP는 팔·다리끼리의 정밀 충돌을 생략하고, 몸통·머리와 벽 장애물·바닥 충돌만 처리한다.

### 피로 분류표

아래를 위에서부터 적용한다. 붙어 있는 손 각각에 같은 분류의 변화율을 적용한다. 단위는 1초당 점수다. 접점을 분리한 Dragging과 소유 터치가 없는 Free의 손은 모두 +15로 회복하며 최대 100이다. 피로 소모가 꺼진 보조 모드에서는 감소만 0으로 대체한다. 피로 경고는 25 이하에서 진입하고 35 이상에서 해제한다.

| 조건 | 붙은 손의 변화율 |
| --- | --- |
| 시작/휴식 플랫폼 위 안정 자세 | +15 |
| 유효 지지 발 2개, 몸통 속도 0.10m/s 이하 | +10 |
| 유효 지지 발 2개, 이동 중 | -2 |
| 유효 지지 발 1개, 붙은 손 2개 | -3 |
| 유효 지지 발 1개, 붙은 손 1개 | -8 |
| 유효 지지 발 0개, 붙은 손 2개 | -15 |
| 유효 지지 발 0개, 붙은 손 1개 | -30 |

고정된 자세를 계속 유지하면 마지막 두 조건에서 가득 찬 손은 각각 약 6.7초·3.3초에 소진된다. 실제 게임에서 손발을 옮기면 조건이 바뀐다. 이 숫자로 난이도를 확정하지 않는다.

## 오류와 복구

- 불가능한 신규 접점은 거부한다. 이를 해결하려고 기존 팔다리를 강제로 늘리지 않는다.
- 수치 오류가 발생하면 틱 전체와 미발행 이벤트를 버리고 마지막 검증 상태로 즉시 자동 일시정지한다. 시간·피로·성공 유지·슬롯 점유를 일부만 되돌리지 않는다. 포인터 바인딩은 모두 제거한다.
- 복구 버튼은 체크포인트 또는 루트 처음의 검증된 자세를 사용한다. 문제가 난 동일 틱을 자동 반복하거나 사용자 release를 재실행하지 않는다. 오류 복구 시 기록 자격은 [15](15_runtime_contract.md)에 따른다. 사용자 추락 횟수는 증가시키지 않는다.
- 이 복구는 손을 일부러 놓거나 피로가 소진된 정상 실패를 취소하는 용도로 사용하지 않는다.
- 위치·속도 상한, 유한수 검사, 슬롯 중복 점유 검사, 관절 길이 검사를 둔다. 잘못된 레벨 데이터는 플레이 전에 거부한다.

## G2 통과 과제

한 손 매달림, 양손 버티기, 높은 발로 일어서기, 대각선 한 손·한 발 이동, 좌우 교차, 같은 슬롯 경합, 새 접점 조합 불가, 전부 분리, 빠른 반복 입력, 카메라 추적, 30/60FPS에서 같은 시나리오를 확인한다. 피로 소모를 끈 진단 조건에서 지지점이 고정된 30초 동안 접점 오차가 0.02m를 넘지 않고 몸통이 계속 상승하지 않아야 한다. 피로 켠 상태의 자연스러운 미끄러짐은 이 정적 안정성 검사와 분리한다.
