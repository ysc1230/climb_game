# 10. 검증·품질 계획

**이 문서는 앞으로 수행할 검증 계획이다. 현재 게임 코드·빌드가 없으므로 아래 시험은 아직 실행하지 않았다.** 문서 검수와 게임 검증 결과를 구별한다.

사용자는 개발 및 기기 실행 검증을 현재 작업에서 제외했다. 아래 게이트는 후속 개발의 품질 기준이며 이번 설계 인계의 완료 조건이 아니다. 문서 검수는 [v0.3 인계](21_design_readiness_v0_3.md)와 [v0.4 참고 반영](22_reference_art_direction.md)에 별도로 기록한다.

## 우선순위와 단계

| 게이트 | 검증 대상 | 다음 단계 진입 조건 |
| --- | --- | --- |
| G0 | 참고 이미지·기기 자세·기술 범위 | 이미지 비교 기준과 검증 기기 범위를 기록 |
| G1 | 실제 네 손가락 조작 | 소유권 오류 0건, 식별·편안함 목표 충족 |
| G2 | 접점·몸통·IK·피로 | 기본 경로 완등, 제약 폭주·무한 상승 없음 |
| G3 | 완성도 검증 장면 | T01/R01 전체 흐름, 아트 비교, 목표 기기 성능 |
| G4 | 12개 스테이지 | 모든 의도 경로·해금·보조 기록 확인 |
| G5 | 배포 준비 | 중단·세이브·성능·설치 및 치명 오류 조건 충족 |

G0 중 참고 REF01의 수신·분석은 완료했다. 검증 기기 선정이나 실제 비교 장면은 아직 없으므로 G0 전체·G3가 통과된 것은 아니다. G1~G5의 구현·실행은 현재 요청 범위에서 제외한다. 이후 아트 비교에는 22의 ART01~ART06을 사용한다.

| IN12 | 다른 화면 비율·UI 배율·60/120Hz | 감도 일관성, 손발 바뀜 없음 |

소유권 자동/수동 재현 100세트에서 잘못된 배정 0건을 초기 기술 통과 기준으로 한다. 네 손가락 입력은 실제 기기로 판정한다. 에디터 마우스, 두 손가락 테스트, API 존재 여부만으로 IN02 통과 처리하지 않는다.

## 성능 예산과 측정

아래는 선정할 목표 기기의 release 빌드 기준 내부 목표이며 엔진의 보장 성능이 아니다. 기기·OS·해상도·렌더러·품질·배터리 상태·주변 온도를 함께 기록한다.

| 지표 | 초기 목표 | 측정 |
| --- | --- | --- |
| 프레임 시간 | 60FPS 모드 중앙값 ≤16.7ms, p95 ≤20ms, p99 ≤33.3ms | 10분 플레이 캡처 |
| 저사양 모드 | 30FPS 표시, 게임 규칙 60Hz 유지 | 같은 루트 결과 비교 |
| 게임 틱 CPU | 평균 ≤4ms, p95 ≤8ms | profiler, 자세 solver 구분 |
| 터치→시각 반응 | p95 ≤100ms | 실제 기기 고속 촬영과 입력 시각 동기화 |
| 메모리 | Android PSS 최대 512MiB 이내 가설 | 첫 실행·플레이·20회 재시도 비교 |
| 로딩 | 홈 첫 진입 ≤4초, 재시도 탭→조작 가능 p95 ≤1초 | 릴리스/오프라인/동일 장치 |
| 열 지속성 | 마지막 5분 평균 FPS가 첫 5분 대비 20% 넘게 저하하지 않음 | 충전/외기 조건을 통일 |
| 누수 | 20회 재시도 후 지속적인 메모리 증가 추세 없음 | 캐시 안정화 후 비교 |

프레임 시간과 입력 지연을 서로 대체하지 않는다. 60FPS라도 터치 큐 지연이 클 수 있다. 프로파일러가 추가한 비용과 계측되지 않는 GPU 시간을 결과에 명시한다. 이 기준을 못 맞추면 장식/그림자/해상도부터 줄이고 판정 표시와 입력 처리 품질을 유지한다.

## 사용자 테스트

초기 5~8명에게 조작 설명 없이 T01과 R01을 제공한다. 10분 동안 기기를 놓은 자세와 손에 든 자세를 구분해 관찰한다. 화면 녹화/손 촬영은 테스트 참여자가 허용한 범위에서만 진행한다. 수집 지표는 첫 완등, 팔다리 오선택, 이유 없는 release, 손가락 재배치 빈도, 불편도, 실패 원인 이해, 자발적 재시도다.

[제품 기획](01_product_brief.md)의 80% 튜토리얼 완료, 오선택 5% 미만, 불편도 중앙값 3/10 이하 목표를 적용한다. 실패하면 패드 크기·위치·감도·잡기 규칙을 먼저 조정한다. 동시에 많은 요소를 바꾸지 않고 이전 버전과 결과를 비교한다.

## 출시 차단 결함

팔다리 오배정, 정상 입력의 소실, 원인 없는 반복 추락, 조작에 의한 물리 폭주, 데이터 손실, 진행 불가 루트, 재현 가능한 충돌, 지원 기기에서 조작을 방해하는 발열·프레임 저하는 해결 전 출시하지 않는다. 경미한 장식 수정과 신규 콘텐츠는 별도 우선순위로 관리한다.

## 사용자 테스트 운영표

1인당 10분 기본 세션은 배치 확인 1분, T01 3분, T02/T03 중 한 과제 2분, R01 3분, 불편도·실패 원인 질문 1분으로 나눈다. 튜토리얼 전체 완주와 장시간 평가는 별도 세션으로 한다. 진행자가 정답 동작을 알려준 경우 해당 과제의 자력 성공으로 세지 않는다.

| 기록 항목 | 정의 |
| --- | --- |
| 팔다리 오선택률 | 플레이어가 미리 밝힌 대상과 최초 배정 팔다리가 다른 횟수 / 의도 확인 과제 수 |
| 잡기 성공률 | 정상 release 중 유효 접점 성공 수 / 잡기 의도가 확인된 release 수 |
| 손가락 재배치 | 목표 슬롯에 도달하기 전 손가락 위치 때문에 중단한 횟수 |
| 첫 완등 | 추가 설명 없는 T01/R01 최초 성공 시간, 실패 시 미완료 표시 |
| 불편도 | 손/손목 0~10 자기보고, 자세·기기별 구분 |
| 실패 이해 | 실제 실패 원인과 사용자가 말한 이유 일치 여부 |

한 참가자의 10분 결과와 오선택 측정을 위한 40회 별도 과제를 혼동하지 않는다. 표본 5명이라면 80% 통과 기준은 최소 4명, 8명이라면 최소 7명이다. 소수 표본의 결과는 시장 전체 비율로 주장하지 않는다.

튜닝은 패드 배치 → 감도/데드존 → 후보 반경 → 몸통 비용/속도 → 피로 → 루트/시간 메달 순서로 한다. 같은 비교 라운드에서 한 묶음만 바꿔 원인을 추적한다. 기록에는 이전/이후 값, tuning_version, 대상 기기, 개선·악화 지표를 남긴다. 아직 이 테스트를 수행한 결과는 없다.
