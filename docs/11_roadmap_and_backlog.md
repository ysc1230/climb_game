# 11. 개발 계획·백로그

## 현재 단계

설계 문서 작성 단계다. 사용자의 최신 요청에 따라 **개발 및 기기 실행 검증을 제외한다.** 아래 항목은 이후 구현할 작업 목록이며 GitHub 이슈나 완료된 기능을 뜻하지 않는다. 사용자가 개발 시작을 요청하면 G1부터 작은 범위로 구현한다. 첫 빌드의 목적은 네 손가락 조작의 실제 기기 검증이다.

현재 문서 작업은 [18. 화면·설정](18_screen_spec.md), [19. 레벨 저작](19_content_authoring.md), [20. 아트 의뢰](20_art_production_brief.md), [21. 설계 인계](21_design_readiness_v0_3.md)까지 구체화했다. 아래 M0의 실제 참고 분석·엔진 버전 고정과 M1~M6의 실행 결과를 이번 완료 조건으로 요구하지 않는다. 41~60 작업일은 향후 제품 개발의 초기 추정이며 이번 문서 작성에 걸린 기간이나 약속된 일정이 아니다.

v0.4에서 [REF01 분석](22_reference_art_direction.md)을 추가해 참고 입력과 아트 방향을 구체화했다. B01의 문서 분석은 수행했지만 캐릭터 시안·대표 장면·기기 검수는 미수행이다. 이를 M0 전체 또는 후속 개발 완료로 표시하지 않는다.

## 단계별 계획

| 단계 | 산출물 | 의존성/종료 조건 | 작업일 추정 |

3D 제작과 모바일 게임 개발을 수행할 수 있는 1인이 전일 작업한다는 가정의 작업량이며, 현재 확인된 실적이나 견적이 아니다. 주 5일이면 약 8~12주 규모다. 업무 외 개발, 학습, 아트 외주 대기, 이미지 표현의 복잡도, 수정 횟수에 따라 달라진다. REF01에서 요구되는 선·질감·접촉 품질을 실제 제작·통합하는 작업량은 대표 장면 이후 재산정한다. iOS 출시, 온라인 기능, 광고·결제, 시장 홍보는 합계에 포함하지 않는다.

M0의 REF01 분석은 반영했다. M1 코드 착수 자체는 현재 요청 범위를 벗어나며, M4는 G1/G2와 대표 아트 방향 확인 이후 시작한다. 한 사람이 작업하면 병행한다고 실제 작업량이 줄어들지는 않는다.

## 첫 구현 요청에 대한 권장 범위

첫 요청은 B03~B07의 작은 검증 빌드로 제한하는 것이 효율적이다. 네 패드, 네 개의 표시 말단, 후보 홀드 몇 개, 터치 소유권 표시, 취소/재개, APK 내보내기만 만든다. 조작감이 확인되면 B08~B13으로 실제 등반을 붙인다. 최종 아트와 전체 12개 스테이지를 첫 코드 변경에 한꺼번에 넣지 않는다.

v0.2에서 추가한 실행 규칙·스테이지 상세·경계 검증은 기존 작업의 수락 조건을 구체화한 것이다. 온라인 기능이나 콘텐츠 수를 늘린 변경이 아니다. 기존 41~60 작업일은 여전히 미검증 추정이며 상세 설계만으로 공수를 확정하지 않는다.

## 변경·작업 관리

- 기능 작업은 관련 문서·수락 기준·검증 결과를 같은 변경에서 연결한다.
- 한 PR/커밋은 입력, 자세, 저장 등 검토 가능한 단위로 나눈다. 이번에는 설계 문서만 저장한다.
- 새로운 아이디어는 MVP 필수인지 P2인지 먼저 분류한다. 기존 사용자 요구를 조용히 삭제하지 않는다.
- 리깅 비율·잡기 규칙·피로·카메라 축 변경은 루트와 테스트를 다시 검토한다.
- 구현 시작 후에는 완료 항목에 빌드·기기·영상/로그 근거를 붙인다. 문서만 있다는 이유로 완료 처리하지 않는다.

## 역할과 외부 제작

개발 담당은 입력·물리·도구·저장·통합을, 아트 담당은 모델·리그·재질·UI를, QA는 실제 기기·루트·저장·입력 검증을 맡는 역할 분리가 가능하다. 이는 인력 계획이며 이번 작업에서 별도 에이전트나 사람에게 업무를 발송한 것이 아니다. 외주를 맡긴다면 캐릭터 1종과 한 장면을 먼저 발주해 품질을 확인하고 전체 제작으로 확대한다.

## v0.5 동작 개편의 선행 작업

사용자 보고인 지속 회전과 동작 제약 부족에 대한 조사·설계는 24/04/25에 있다. 후속 개발에서는 25의 순서(회전 프레임 → 모든 말단의 기하 제약 → 하중·체중 이동 → 무브 → 루트 재검수)를 기존 콘텐츠 확대보다 먼저 수행한다. 작업의 구현·기기 검증은 이번 요청 범위에 포함하지 않는다.

기존 공수는 새 3D 제약·하중 계산의 성능과 리그 수정량을 반영하지 않은 추정이다. 일정 확약에 사용하지 않으며 별도 구현 계획에서 갱신한다.
