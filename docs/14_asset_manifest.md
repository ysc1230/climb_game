# 14. 에셋 제작·발주 목록

아래는 목표 제작·검수 목록이다. 23에는 CH01·첫 3D 장면의 제작 기록이 있으므로 전체를 미제작으로 보지 않는다. 다만 최종 납품·검수 완료 여부는 항목별로 확인해야 한다. 본 목록은 제작 의뢰와 통합 검수에 사용할 초안이다. REF01 반영 후에도 수량은 유지하며 실제 대표 장면 제작 결과에 따라 품질·공수를 재검토한다.

아래 수량을 실제 의뢰로 옮길 때의 제출 묶음·리그 포즈·비교표·음원 규격은 [20. 아트 제작 의뢰서](20_art_production_brief.md)를 사용한다. 실행 캡처와 엔진 통합 수락 조건은 이후 작업이며 이번에는 수행하지 않는다.

## 대표 장면 최소 납품

CH01~03, 손 잡기 포즈, 벽 일부, 큰 손홀드·발판·정상, 임시 HUD, 기본 광원으로 R01의 한 화면을 구성한다. 이 단계의 통합 캡처가 참고 품질과 맞는지 확인한 후 미제작 자산을 확대한다. 제작 순서는 외형 대량 생산보다 리깅·접촉 품질과 엔진 내 표현 확인을 우선한다.

## 자산별 기록 필드

| 필드 | 내용 |
| --- | --- |
| asset_id / version | 영구 식별자와 개정 버전 |
| source_path / export_path | 편집 원본·엔진용 산출물 경로 |
| creator / source_url | 제작자·취득 출처 |
| usage_terms / license_file | 사용 범위·출처 표기·허가 문서 |
| tool_version / export_settings | 재현 가능한 제작·내보내기 설정 |
| scale / origin / axis | 단위·원점·축 |
| rig_contract | 뼈 이름·방향·rest pose·pole 방향 |
| budgets | 삼각형·재질·뼈·텍스처·음원 길이 |
| validation | 엔진 버전·검수 기기·통과 포즈·캡처 |
| status | Brief/Blockout/Review/Accepted/Integrated |

아트 산출물과 콘텐츠 데이터는 같은 asset_id로 연결한다. 파일 이름만 바꿔 연결을 끊지 않는다. 에셋을 교체할 때 슬롯 위치와 모델 기준점이 달라지면 해당 루트를 다시 검증한다.

REF01은 이 게임의 제작 에셋 ID가 아니라 참고 자료 ID다. [22](22_reference_art_direction.md)의 따뜻한 흙빛·얇은 선·무광·독자적 등반복 요구를 CH/EN/HD/UI 제작에 적용한다. 기존 8개 홀드 메시·3개 벽 모듈 안에서 시각 방향을 구체화하며 원본 캐릭터나 배경 메시를 납품 대상으로 추가하지 않는다.

## 파일 규격

3D 원본은 편집 가능한 형식과 glTF/GLB 산출물을 함께 관리한다. 텍스처는 무손실 편집 원본과 엔진 임포트 설정을 보존한다. UI는 편집 가능한 벡터/레이어 원본과 사용 크기의 산출물을 구분한다. 음원은 고품질 원본과 모바일용 임포트 설정을 함께 기록한다. 엔진 임포트 캐시·파생 빌드·서명 자료를 아트 원본처럼 커밋하지 않는다.

대용량 바이너리는 실제 파일 크기를 확인한 뒤 Git LFS 또는 적절한 배포 저장 방식을 선택한다. LFS 사용을 선언만 하고 객체가 업로드되지 않은 상태로 납품하지 않는다. 이번 문서 단계에는 대용량 에셋이 없다.

## 외주/제작 수락 조건

- 정해진 엔진 버전에서 외형·재질·리그가 재현된다.
- 기존 도달 거리와 슬롯 계약을 바꾸지 않는다. 변경이 필요하면 먼저 영향 범위를 기록한다.
- 기본·벌림·교차·한 손 매달림·고발 자세에서 심한 변형이나 관통이 없다.
- 최종 화면 크기에서 손/발/홀드 종류가 구분된다.
- 아트 및 성능 기준을 함께 만족하는 실제 실행 캡처를 제공한다.
- 사용 범위와 원본 편집·수정·배포에 필요한 권한 기록이 있다.

파일이 전달되었다는 사실과 실제 엔진에 통합되어 검증되었다는 상태를 별도로 관리한다.

## v0.5 동작 개편의 에셋 영향

캐릭터 수·의상 수를 늘리지 않는다. CH01 리그에 휴지 축·pole·관절 제한·접촉 프레임 정보를 명시하고 20/25의 회전·교차·드롭니·플래깅 검수 자세를 추가한다. 현재 모델의 twist·스킨 가중치 수정량은 실행 재현 이후 판단한다. 이번 작업에서 모델·텍스처·리그 파일을 수정하지 않았다.
