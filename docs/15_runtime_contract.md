# 15. 실행 순서·상태·복구 계약

설계 v0.2 · 2026-10-30 · 코드 구현 전

기존 문서에서 구현자의 추측이 필요했던 사건 순서와 경계 조건을 정한다. **03은 입력, 04는 자세와 수치, 09는 데이터 형식, 이 문서는 시간·상태 전환·확정 순서의 기준**이다. 이 문서의 처리 결과는 앞으로 구현할 동작이며 실제 실행 결과가 아니다.

## 상태와 시간

| 상태 | 말단 조작 | 게임 시간/피로 | 이탈 조건 |
| --- | --- | --- | --- |
| Ready | 시작 전 패드 배치·기기 확인만 | 모두 멈춤 | 시작 버튼 |
| Climbing / Supported | 네 말단 조작 | 시간·피로·목표 판정 진행 | 무지지·일시정지·완등 |
| Climbing / Grace | 말단 이동·잡기 가능, 몸통 정지 | 시간·Free 손 회복 진행, 목표 유지 정지 | 지지 회복 또는 유예 종료 |
| Paused | 기본적으로 없음, 준비 중 새 터치 배정만 | 게임 시간·피로·유예·카메라 멈춤 | 재개·종료·복구 |
| Falling | 새로운 잡기 요청 거부 | 시도 시간·낙하 연출만 진행 | 실패선 또는 낙하 시간 상한 |
| Failed | 결과 UI만 | 모두 멈춤 | 체크포인트 복귀·처음부터·루트 선택 |
| Cleared | 결과 UI만 | 모두 멈춤 | 다음 루트·다시 시작·홈 |

Paused는 들어오기 전 상태와 Climbing의 내부 상태를 보존한다. Falling에서 앱이 중단되었다고 Climbing으로 돌아가지 않는다. Failed/Cleared에서 앱이 중단되면 같은 결과 화면으로 복귀한다.

게임의 권위 시간은 60Hz의 확정된 틱 수다. 유예는 9틱, 정상/체크포인트 유지는 36틱이다. 경과 초는 확정된 누적 틱 수를 60으로 나눈다. HUD에서는 표시 자릿수만 반올림하고 판정은 정수 틱을 쓴다. 타이머 시작 시 이미 끝난 틱을 중복 가산하지 않는다.

재개 준비 3초는 게임 틱이 아니라 앱 전경에서 흐르는 단조 증가 UI 시간이다. 앱이 다시 중단되면 준비를 취소하고 Paused에 남는다. 전경 업데이트가 0.25초 넘게 끊기거나 미처리 게임 시간이 0.10초를 초과하면 자동 일시정지하고 밀린 시간을 버린다. 이 일시정지 시간은 기록에서 제외한다. 매 프레임 최대 4틱의 따라잡기는 허용하지만 조용히 게임 시간을 느리게 만드는 수단으로 사용하지 않는다.

## 한 틱의 확정 순서

| 순서 | 처리 | 다음 단계가 읽는 내용 |
| --- | --- | --- |
| 0 | 앱 취소·포커스·일시정지 검사 | 중단이면 이 틱을 실행하지 않음 |
| 1 | 포인터·제스처 명령 검증 | 유효 세대·소유권의 명령만 통과 |
| 2 | 의도 분리·드래그 이동 적용 | 빈 슬롯, 실제 말단, 요청 목표 |
| 3 | release 후보 재검사 | 후보·거부 사유·신규 요청 조합 |
| 4 | 잡기 조합 평가, 잠정 접점 적용 | 기존 접점을 포함한 전체 상태 |
| 5 | 자세 해법과 최종 지지 판정 | 유효 자세·지지 발/손·플랫폼 |
| 6 | 손 피로 갱신, 0인 손 분리 | 최종 접점·최종 지지 |
| 7 | 무지지 유예/추락 전환 | Falling 여부, 추락 수 |
| 8 | 정상·체크포인트·경과 시간 | 단일 세션 결과 |
| 9 | 전체 상태와 이벤트 확정 | UI·소리·진동·저장용 스냅숏 |

중간 단계에서 구조·수치 오류가 나오면 그 틱의 변경과 미발행 이벤트를 모두 폐기한다. 이전 슬롯은 복구했는데 잡기 소리만 나거나, 시간만 증가하는 부분 확정을 허용하지 않는다. 유효하지만 움직일 수 없는 자세, 후보가 없는 release, 점유 충돌은 정상 게임 결과이며 수치 오류가 아니다.

잡기가 잠정 성공했더라도 같은 틱의 피로 소진으로 즉시 분리되면 최종 피드백은 미끄러짐을 우선한다. 성공·실패 화면과 보상 이벤트는 한 틱에 동시에 나오지 않는다.

## 같은 틱에 몰린 입력

입력에는 도착 순서 번호, 입력 세대, 터치 ID, 제스처 번호를 둔다. 서로 다른 터치의 순서는 기록하되 활성 팔다리 배정에 쓰지 않는다. 연속 drag만 합산할 수 있고 down/up/cancel을 넘어 합산하지 않는다.

동일 팔다리의 release 이후 다시 down이 같은 틱에 들어오면 이전 제스처의 잡기 배치를 먼저 끝낸 뒤 새 제스처를 처리한다. 이 경계에서 게임 시간·피로·몸통 운동을 한 번 더 진행하지 않는다. 서로 다른 팔다리의 동시 release는 다음 같은-팔다리 제스처 경계 또는 틱 끝까지 모아 조합 평가한다. 따라서 한 팔다리의 두 잡기 요청이 하나로 덮어써지지 않는다.

각 배치에서 분리는 먼저, 신규 슬롯 배정은 이후에 적용한다. 기존 점유자 우선 → 가능한 신규 접점 수 최대 → 말단과 슬롯 거리 합 최소 → 이벤트 순번 → LH/RH/LF/RF의 고정 비교 순서로 결정한다. 고정 비교 순서는 완전 동률일 때만 사용한다. 먼저 누른 손가락을 LH로 배정하는 규칙과 무관하다.

이미 처리한 제스처의 release가 중복 도착하면 무시한다. 존재하지 않는 터치의 drag/up으로 새 소유권을 만들지 않는다. OS 취소와 정상 up이 함께 도착하면 취소가 우선하며 해당 틱의 미확정 게임 입력을 폐기한다.

## 유예와 추락 경계

마지막 손이 분리되고 플랫폼 지지가 없는 틱이 확정될 때 무지지 카운트가 처음 1이 된다. 유효 손/플랫폼 지지를 다시 얻으면 0으로 돌아간다. 잡기·피로 결과를 먼저 계산하므로 9번째 무지지 후보 틱에서도 유효 접점이 먼저 성립하면 추락하지 않는다. 그 틱 끝까지 지지가 없으면 9로 확정되는 순간 Falling이다. 이후 도착한 release는 잡기를 만들지 않는다.

Grace에서는 골반을 마지막 유효 위치에 유지한다. 이는 입력 순서의 작은 차이를 흡수하는 의도적인 게임 규칙이다. 실제로 떨어지면서 잡는 동작을 구현한 것이 아니다. 카운트와 피로는 일시정지 후에도 이어지며, 재개했다고 새 9틱을 받지 않는다.

Falling 진입 시 한 번만 다음을 수행한다.

1. 추락 수를 1 증가시키고 실패 원인과 당시 높이를 기록한다.
2. 모든 슬롯을 해제하고 포인터 소유권을 제거한다.
3. 정상/체크포인트 유지 카운트를 초기화한다.
4. 중력 기반 낙하 표현을 시작하고 카메라 추적을 멈춘다.
5. 재개용 메타데이터 저장을 요청한다. 쓰기 완료를 기다리며 화면을 멈추지는 않는다.

실패선을 지나거나 최대 연출 시간이 끝나면 Failed로 간다. 이때 추락 수를 다시 늘리지 않는다. 낙하 중 화면이 꺼지면 상태를 보존하고, 재개 버튼은 남은 낙하를 이어갈 뿐 잡기를 다시 허용하지 않는다.

## 중단·재개 절차

일시정지 시 Attached/ArmedAttached는 Attached로, 접점을 놓은 Dragging은 현재 위치의 Free로 정리한다. 네 포인터와 미소비 이동량을 모두 지우고 입력 세대를 증가시킨다. 접점을 새로 만들거나 체력을 회복시키지 않는다. 카메라와 물리 보간 상태도 같은 검증 스냅숏에 고정한다.

Climbing으로 돌아갈 때는 재개 버튼의 UI 터치가 끝난 후 3초 준비 화면을 연다. 준비 중에는 패드의 새 down을 받아 소유권만 정할 수 있다. 움직임·잡기·피로는 처리하지 않는다. 준비 중 손가락을 떼면 소유권만 제거한다. 카운트가 끝나는 순간 새 손가락 위치와 현재 말단을 기준점으로 삼는다.

이후 Attached에 배정된 손가락은 ArmedAttached, Free에 배정된 손가락은 Dragging으로 시작한다. 배정되지 않은 Free는 일반 휴식 자세를 따른다. 준비 중 움직인 거리를 재생하지 않는다. 재개 직전에도 지지가 없었다면 남아 있던 Grace 시간만 제공한다. 일반 Falling 복귀에는 조작 준비가 필요 없으므로 별도의 3초 카운트를 넣지 않는다.

화면 크기·배율 변경 후 저장된 패드 위치를 다시 제한하고 준비를 시작한다. 연속 취소, 제스처 간섭, 창 전환이 발생해도 마지막 유효 상태를 유지한다.

## 체크포인트와 재시도

플랫폼의 두 발 지지, 몸통 속도 0.10m/s 이하, 유효 자세가 36틱 유지되면 활성화한다. 손이 붙어 있어도 되고 없어도 된다. 발 슬롯 하나가 바뀌거나 지지/속도 조건을 잃으면 유지 카운트를 0으로 한다. Paused는 카운트를 보존한다. 일반 루트의 체크포인트는 R06/R09의 각각 1개다.

체크포인트 데이터는 복귀 골반·회전, 네 접점, 피로 100, 속도 0을 가진 사전 검증된 자세다. 활성화 당시 캐릭터를 이 자세로 순간 이동시키지는 않는다. 복귀 버튼을 누른 경우에만 짧은 화면 전환 안에서 이 상태를 적용하고 입력·보간·카메라를 초기화한다. 같은 run_id, 누적 시간, 추락 수는 유지한다. 활성화·복귀 시 시간을 줄이지 않는다.

| 사용자 행동 | 시도·체크포인트 | 기록 처리 |
| --- | --- | --- |
| 일시정지 후 재개 | 정확한 현재 상태 유지 | 기존 자격 유지 |
| 실패 후 체크포인트 복귀 | 같은 run_id, 최신 CP | 시간·추락 수 누적 |
| 처음부터 다시 | 새 run_id, 초기 자세, CP 비활성 | 시간·추락 수 초기화 |
| 루트 선택/홈으로 나가기 | 진행 중 시도를 포기 처리 | 미완료 보상 없음, 다음 진입은 새 시도 |
| 앱 프로세스가 끝난 뒤 이어하기 | 버전이 맞는 마지막 CP, 없으면 시작 자세 | recovered 기록으로 분류 |
| 콘텐츠/조정 버전 불일치 | 이전 시도의 재개 포기, 새 시작 선택 | 이전 완료 기록은 보존 |
| 내부 오류로 안전 자세 복구 | 같은 콘텐츠의 CP/시작 | recovered 기록, 추락 수 가산 없음 |

홈의 “이어하기”는 유효한 중단 세션이 있을 때만 표시한다. 단순히 가장 최근 루트를 다시 시작하는 버튼은 “최근 루트”로 구분한다.

## 메달·기록 자격

시도는 route_id, content_version, tuning_version, assist_flags, recovery_flag를 가진다. 일반 기록은 보조 플래그와 복구 플래그가 모두 없는 시도다. 보조 플래그는 시도 중 켜진 값을 합집합으로 누적한다. recovery_flag는 한 번 true가 되면 해당 시도 끝까지 유지한다.

| 기록 종류 | 완등·다음 루트·색상 해금 | 무추락 메달 | 시간 메달·최고 시간 |
| --- | --- | --- | --- |
| 일반 | 인정 | 추락 0일 때 인정 | 기준 이하일 때 일반 기록에 인정 |
| 보조 | 인정 | 추락 0일 때 보조 기록에 인정 | 같은 보조 조합 기록에만 인정 |
| 복구(recovered) | 인정 | 부여하지 않음 | 비교·갱신하지 않음 |

복구는 공중 상태 대신 과거 안전 자세로 돌아가기 때문에 시간과 실패 없는 플레이를 동일하게 비교할 수 없다. 결과 화면에 “복구 후 완등 · 진행도 반영”을 표시한다. 시간은 참고용으로 보여줄 수 있지만 최고기록에 사용하지 않는다. 이를 온라인 부정행위 방지 시스템으로 표현하지 않는다.

무추락·시간 메달은 완등을 전제로 한다. 메달은 각 기록 구분 안에서 누적 OR로 저장하고 가장 빠른 시간은 최소값으로 저장한다. 시간 경계는 완료 시점의 누적 틱이 기준 초×60 이하인지로 판단한다. 과거 획득 메달을 느린 재도전으로 지우지 않는다.

기본 색상은 처음부터 제공하고 R03 완등에 두 번째, R09 완등에 세 번째 색상을 연다. 일반/보조/복구 완등 모두 외형 해금에 사용할 수 있다. 사용자에게 능력치가 달라진다는 인상을 주지 않는다.

## 튜토리얼 세션의 예외

튜토리얼은 별도 `tutorial` 기록 종류이며 일반 루트 메달·최고 시간에 포함하지 않는다. 설명 화면과 준비 단계에서는 게임 시간이 멈춘다. T01/T02는 피로 감소를 끄고, T03은 피로 경고를 배우는 구간에만 지정된 시작 피로와 일반 변화율을 적용한다. 설정과 구간 시작 상태를 화면에 표시한다.

T03의 의도된 추락 체험은 안내된 시범 구간으로 구분하고 현재 구간 처음으로 복귀한다. 튜토리얼 완료 여부에 페널티를 주지 않는다. 구간을 통과해야 다음 안내가 열리며, 동시 손가락 사용을 판단하는 조건은 [16](16_stage_specs.md)에 따른다.

## 결과와 저장의 거래 단위

완등이 확정되면 결과 ID를 run_id에 귀속시키고 메달·진행·외형·현재 세션 종료를 하나의 저장 요청으로 만든다. 저장 요청 재시도는 같은 결과 ID를 사용한다. 늦게 도착한 낮은 저장 일련번호는 최신 상태를 덮어쓸 수 없다.

저장 실패 중에도 완등 화면은 볼 수 있지만 “기록 저장 실패”를 표시한다. 앱이 살아 있는 동안 최신 결과를 메모리에 유지하고 재시도한다. 프로세스 종료 전에 쓰기가 성공하지 않은 결과까지 보존한다고 보장하지 않는다. 이미 성공한 이전 저장을 삭제하거나 깨진 새 파일로 덮어쓰지 않는다.

최종 상태 이벤트와 표시 이벤트를 구분한다. 진단에는 접점 분리·잠정 잡기 등 상세 사유를 남길 수 있지만, 사용자 사운드·진동·결과·저장은 확정된 최종 상태만 따른다.
