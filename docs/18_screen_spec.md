# 18. 화면 동작·설정·문구 명세

설계 v0.4 · 2026-10-30 · 구현 전

[05](05_screens_and_ux.md)의 화면 구성을 실제 버튼·상태·설정 단위로 구체화한다. 화면은 [15](15_runtime_contract.md)의 확정된 세션 상태를 표시하며 직접 접점·시간·기록을 바꾸지 않는다. 아래 기본값은 제작을 위한 제안이며 사용성 시험 결과가 아니다.

## 공통 화면 규칙

- 메뉴는 중앙 안전영역을 사용한다. 설정처럼 항목이 많은 화면은 게임을 정지하고 안전영역 전체를 사용한다. 네 조작 패드와 메뉴 버튼을 동시에 활성화하지 않는다.
- 화면 제목 → 현재 상태/설명 → 주 행동 → 보조 행동 순서로 읽히게 한다. 한 화면의 강조 버튼은 1개다.
- 메뉴 선택은 눌렀다 떼는 정상 UI 동작에서 1회 처리한다. 전환 중 반복 입력은 중복 실행하지 않고, 새 화면에 이전 터치의 release를 전달하지 않는다.
- 뒤로 가기는 플레이에서 일시정지, 설정에서 변경 취소 확인, 결과에서 루트 목록으로 동작한다. 일시정지 화면의 뒤로 가기는 재개 버튼과 같은 준비 절차를 따른다.
- 설정·확인 창이 열려 있는 동안 게임 시간·피로·유예는 멈춘다. 중단 상태에서 설정을 닫아도 자동으로 등반을 재개하지 않는다.
- 게임을 홈/목록으로 나가는 행동은 미완료 시도를 포기한다. 앱 백그라운드 전환은 일시정지다. 두 행동을 같은 “나가기” 처리로 묶지 않는다.
- 가로 방향을 기본으로 하고 화면 크기·안전영역이 변하면 자동 정지 후 배치를 다시 계산한다. 이 단계에서 기기의 방향 전환 동작을 검증했다는 뜻은 아니다.

## 화면별 상태와 행동

| 홈 / 처음 | 튜토리얼과 기본 외형 | 조작 배우기 | 루트 목록, 설정 |

| 루트 목록 / 잠금 | 선행 루트 이름과 완등 조건 | 없음 | 잠긴 카드 선택 시 조건만 안내 |
| 루트 목록 / 해금 | 학습 요소, 일반/보조 메달, 선택한 기록 구분 | 시작하기 | 튜토리얼 다시 보기, 홈. 현재 버전 기록과 이전 버전 기록을 구분 |
| 시작 준비 / Ready | 루트 목표, 활성 보조 옵션 | 시작하기 | 패드 조정, 목록. 버튼 release 후 동일한 3초 준비 절차 적용 |
| 플레이 | 손·발 상태, 후보, 피로, 목표 | 네 패드 | 일시정지. 화면 밖 터치로 임의 팔다리 선택 금지 |
| 튜토리얼 안내 | 현재 단계의 한 문장·목표 팔다리 | 연습 시작 | 도움말, 일시정지. 단계 조건은 16 문서 기준 |
| 일시정지 / 등반 | 루트·경과 시간·기록 구분 | 계속하기 | 처음부터, 루트 선택, 설정. CP로 임의 이동하는 버튼 없음 |
| 일시정지 / 낙하 | 낙하 중 상태 | 계속하기 | 남은 낙하만 재생. 3초 준비·재잡기 없음 |
| 실패 / CP 활성 | 실패 원인, 도달 높이, 누적 추락 수 | 체크포인트부터 | 처음부터, 루트 선택. CP 재시도는 같은 시도의 시간·추락 수 유지 |
| 실패 / CP 없음 | 실패 원인과 다음 행동 도움말 | 처음부터 다시 | 루트 선택. 새 시도이므로 시간·추락 수 초기화 |
| 완등 / 일반 | 완등·시간·추락·해당 일반 메달 | 다음 루트 | 다시 도전, 목록. 이미 얻은 메달은 유지 |
| 완등 / 보조 | 사용한 보조 항목과 보조 기록 | 다음 루트 | 일반 기록과 합쳐 표시하지 않음 |
| 완등 / 복구 | “복구 후 완등 · 진행도 반영” | 다음 루트 | 시간은 참고값, 무추락/시간 메달은 “이 시도에서는 기록하지 않음” |
| 튜토리얼 완료 | 익힌 조작과 다음 과제 | 다음 연습 | T03 뒤 R01 시작. 일반 루트 메달 없음 |
| R09 완료 | 전체 루트 완등, 세 번째 색상 | 기록 다시 도전 | 루트 목록. 존재하지 않는 다음 루트 버튼 없음 |
| 설정 | 편집 중 값과 현재 적용 값의 차이 | 적용 | 취소, 기본값. 진행 초기화는 별도 영역 |

최고 도달 높이는 해당 시도의 확정된 골반 Y의 최댓값에서 시작 골반 Y를 뺀 0 이상 값이다. 실패 화면의 정보용이며 메달 조건이 아니다. CP 재시도는 같은 시도의 최댓값을 유지한다. 복구 시에는 저장된 값을 사용하고, 마지막 저장 뒤의 높이는 사라질 수 있다.

시작 준비의 3초 동안에는 패드 소유권만 배정한다. 준비가 끝나는 순간 입력 기준점을 다시 잡고 첫 게임 틱을 시작한다. 준비 중 앱 중단은 Paused로 돌아간다. 튜토리얼 설명 뒤 연습 시작에도 같은 절차를 쓰되 설명/준비 시간은 과제 제한 시간에 넣지 않는다.

색상은 CH04_01 기본, CH04_02 R03 완등, CH04_03 R09 완등으로 연결한다. 최종 팔레트가 정해지기 전 표시명은 “기본색/색상 2/색상 3”이다. 선택 미리보기 뒤 적용·저장하며 취소하면 이전 색상을 유지한다. 해금했다고 자동으로 착용하지 않는다. 다음 플레이 표시부터 적용하고 판정·도달 거리·기록 자격은 바꾸지 않는다. 실제 색상 이미지와 썸네일은 아직 제작하지 않았다.

v0.4의 REF01 기반 제작 팔레트는 [22](22_reference_art_direction.md)에 있다. 청록·적갈색·아이보리 계열이 시작 제안이며 최종 색상 시안 확정 전까지 위 임시 표시명과 기존 해금 순서를 유지한다.

## 설정 기본값과 저장

설정은 홈 또는 일시정지에서만 변경한다. 한 개의 사용자 프로필에 아래 값을 저장하며 프리셋 여러 개를 관리하는 기능은 MVP에 넣지 않는다. 현재 적용 값에서 편집 사본을 만들고 “적용”에서 전체 유효성 확인 후 한 번에 반영한다. 취소는 사본을 버린다. 음량 미리듣기만 일시적으로 허용하고 취소하면 원래 음량으로 돌아간다.

| 설정 | 기본값·범위 | 적용·표시 규칙 | 기록 자격 영향 |
| --- | --- | --- | --- |
| 패드 위치 | LH(0.11,0.30), LF(0.11,0.72), RH(0.89,0.30), RF(0.89,0.72) | 안전영역 비율 좌표. 05의 22% 구역·24단위 간격 제한 | 없음 |
| 패드 지름 | 각 160, 각각 120~220 논리 단위 | 패드별 조절. 입력 환산에는 해당 패드 지름 사용 | 없음 |
| 패드 불투명도 | 60%, 30~100% | 패드 배경만 변경. 손/발 아이콘·경고의 필수 가독성 유지 | 없음 |
| 이동 감도 | 공통 1.0, 0.6~1.6, 0.1 간격 | 네 패드 공통. 시작 시점 배율과 감도는 제스처 중 바뀌지 않음 | 없음 |
| 피로 숫자 | 끄기 | 손 테두리/패턴 경고는 항상 유지 | 없음 |
| 경과 시간 표시 | 끄기 | 켜면 경과 시간과 시간 메달 기준을 함께 표시 | 없음 |
| 도달 영역 | 조작 중 표시 | “항상 표시” 선택 가능. 자동 이동 없음 | 없음 |
| 색각 보조 | 끄기 | 켜면 아이콘·패턴을 강화하고 상태별 팔레트 적용 | 없음 |
| 메뉴 글자 크기 | 100%, 100/115/130% | 글자·메뉴 재배치. 패드 크기·월드 시야는 별도 | 없음 |
| 배경음 / 효과음 / 환경음 | 60 / 80 / 50%, 각각 0~100% | 효과음을 꺼도 판정과 경고를 시각적으로 제공 | 없음 |
| 진동 | 켜기 | 손 접촉·경고·추락·완등. 발 접촉·메뉴 진동은 MVP에서 끔 | 없음 |
| 화면 흔들림 | 끄기 | 켜도 짧은 표현 효과에만 적용. 논리 카메라·입력 좌표는 고정 | 없음 |
| 그래픽 | 표준 | 표준/낮음 두 단계. 자동 기기 판별은 없음 | 없음 |
| 피로 끄기 | 끄기 | 적용 이후 피로 감소 0, 기존 값은 즉시 100으로 바꾸지 않음. 정상 회복은 유지 | 켠 시도에 fatigue_disabled 누적 |
| 잡기 범위 확대 | 끄기 | 적용 이후 후보 반경 ×1.35. 도달 거리·관절 길이 불변 | 켠 시도에 expanded_candidates 누적 |

현재 시도가 있을 때 보조 값을 편집만 하다가 취소하면 플래그를 추가하지 않는다. 적용하면 이번 시도의 플래그에 합집합으로 누적한다. 이후 끄거나 기본값으로 돌려도 그 시도의 보조 이력은 지워지지 않는다. 다음 새 시도는 그 시점에 적용된 설정으로 시작한다. 복구 플래그는 보조 설정으로 해제되지 않는다.

튜토리얼에서는 구간별 피로 교육 규칙이 우선하며 해당 단계의 “피로 연습 설정”을 표시한다. 보조 설정의 저장 값은 바꾸지 않고 일반 루트에서 다시 사용한다. 튜토리얼 결과는 별도 진행이다.

“기본값”은 편집 사본만 초기화하고 적용 전까지 저장하지 않는다. 진행·메달·외형 해금은 바꾸지 않는다. 화면 변경 때문에 저장 배치를 적용할 수 없으면 05의 제한 → 축소 → 재설정 순서를 사용한다. 자동 보정한 위치/지름은 미리보기에서 알리고 적용 때 저장한다.

그래픽 표준은 렌더 60FPS·3D 해상도 배율 1.0을, 낮음은 렌더 30FPS·배율 0.75와 장식 그림자/파티클 축소를 초기값으로 제안한다. UI는 화면 해상도를 유지한다. 두 단계 모두 게임 판정은 60Hz이고, 홀드·후보·손발 표시를 제거하지 않는다. 그래픽 단계가 엔진 렌더러를 바꾸지는 않는다. 이 값은 특정 기기에서 달성한 결과가 아니다.

## 확인 창·복구·저장 실패

| 발생 조건 | 본문 | 버튼과 결과 |
| --- | --- | --- |
| 진행 중 처음부터 | “현재 시도를 끝내고 처음부터 시작할까요?” | “처음부터”는 새 시도, “돌아가기”는 Paused 유지 |
| 진행 중 홈/목록 이동 | “현재 시도는 끝나며 이어할 수 없어요. 완료한 기록은 유지돼요.” | “나가기”는 포기, “돌아가기”는 Paused 유지 |
| 설정 미적용 뒤로 | “바꾼 설정을 적용하지 않고 돌아갈까요?” | “변경 취소”, “계속 편집” |
| 진행 초기화 | “완료 기록·해금·진행 중 시도를 지워요. 조작과 소리 설정은 유지돼요.” | “진행 초기화”, “취소”. 초기화 확정 시 홈으로 이동하고 튜토리얼 완료 상태도 해제 |
| 재실행 복구 | “마지막 체크포인트에서 이어해요. 없으면 시작점으로 돌아가요. 이번 시도는 진행도만 반영돼요.” | “이어하기”, “처음부터”. 실제 복귀 지점 이름을 함께 표시 |
| 콘텐츠 버전 불일치 | “루트가 바뀌어 이전 시도를 이어할 수 없어요. 완료 기록은 남아 있어요.” | “새로 시작”, “홈으로” |
| 설정 저장 실패 | “설정을 저장하지 못했어요. 다시 시도해 주세요.” | 편집 사본 유지, “다시 저장” 또는 “변경 취소”. 적용 값/보조 플래그는 확정 전 그대로 |
| 게임 결과 저장 실패 | “기록 저장에 실패했어요. 이 화면에서 다시 저장할 수 있어요.” | 메모리의 완료 결과 유지, 같은 result_id로 “다시 저장”. 다음 루트/나가기에는 미저장 안내 |
| 수치 오류 일시정지 | “등반을 잠시 멈췄어요. 안전한 지점에서 다시 시작할 수 있어요.” | “안전 지점으로”는 복구 표시, “처음부터”는 새 시도. 오류 상태를 그대로 계속하기 없음 |

게임 결과의 저장 실패 뒤 다음 루트/홈으로 이동하려면 “아직 저장되지 않은 기록이 있어요” 확인을 거친다. 메모리에 대기 저장을 유지하더라도 프로세스 종료 후 보존을 보장하지 않는다. 낮은 저장 일련번호가 최신 상태를 덮어쓰지 않게 하는 규칙은 09를 따른다. 앱 설정에서의 진행 초기화는 향후 제품 동작 명세이며 이번 작업에서 어떤 실제 기록도 삭제하지 않는다.

## 문구 키와 표현

MVP 작성 언어는 한국어다. 문구 키는 번역과 버튼 동작을 분리하기 위한 식별자이며 이번에 번역 파일을 구현하지 않는다. 아래 키와 문구를 기준으로 화면 간 같은 행동을 같은 이름으로 표시한다.

| 키 | 표시 문구 | 사용 위치 |
| --- | --- | --- |
| action.resume | 계속하기 | 인프로세스 일시정지 |
| action.continue_run | 이어하기 | 유효 저장 시도 |
| action.start | 시작하기 | 새 루트 준비 |
| action.retry_start | 처음부터 다시 | 실패 후 새 시도 |
| action.retry_checkpoint | 체크포인트부터 | 활성 CP가 있는 실패 |
| action.next_route | 다음 루트 | R01~R08 완등 |
| action.apply / action.cancel | 적용 / 취소 | 설정 |
| action.help | 도움말 보기 | 튜토리얼 |

잡기 실패·피로·거리 안내 문구는 05, 튜토리얼 단계별 대본은 16을 사용한다. 하나의 실패에 여러 문장을 겹쳐 내보내지 않는다. 내부 오류 코드·터치 ID·틱 수는 일반 플레이 화면에 표시하지 않는다.

시간은 표시용으로 분:초.소수 2자리, 높이는 소수 1자리 m, 피로 숫자는 0~100 정수로 반올림한다. 메달 판정은 표시값이 아니라 확정된 정수 틱 기준이다. 반올림 때문에 기준과 같아 보이지만 메달을 못 얻는 경우 상세 결과에 “기준 시간 초과”를 표시한다.

## 문서 검토 사례

보조 켜기→취소는 일반 기록 유지, 보조 켜기→적용→끄기는 보조 이력 유지, 설정 기본값은 진행 보존, 복구 완등은 다음 루트 해금, 낙하 중 재개는 낙하 계속, R09 결과에는 다음 루트 없음으로 읽히는지 검토한다. 이는 화면 설계의 일관성 검토이며 UI나 기기 실행 시험을 수행한 기록이 아니다.

## 플레이 화면 위쪽 정보·일시정지 (2026-11-08)

사용자가 참고 이미지를 주고 위쪽을 그렇게 표시하고, 잠깐 멈췄다 다시 할 때의 문구·UI를 예쁘게 바꿔 달라고 했다. 그리기는 `game/scenes/hud.gd`가 맡는다.

- **1줄(위쪽)**
  - 왼쪽: 일시정지 버튼(둥근 사각형, ‖ 기호).
  - 가운데 패널: 문제 이름(일반 문제는 "등급-순서 이름", 예: V4-1 끝까지 버티기. 추락이 있으면 "· 추락 n"), 목표 높이, 진행 점 7개(출발·중간 다섯·깃발).
    - 목표 높이는 정상 홀드가 시작 손 홀드보다 높은 만큼이다.
    - 진행 점은 이번 시도에서 오른 가장 높은 높이로 채우고, 지난 점은 ✓로 표시한다.
  - 오른쪽 패널: 현재 높이(시작 골반에서 오른 높이).
- **2줄**: 왼손·오른손 팔 힘 패널(손 아이콘, "n / 100", 50 이상 초록·25 이상 노랑·그 아래 빨강과 "!").
- **3줄(가운데)**
  - 상태 줄: 지지(방패), 손 하중(L·R %), 무브(신발).
  - 균형 회복 중·지지 없음이면 남은 시간 막대가 줄 아래에 붙는다.
- 세 줄은 화면 높이 222(배율 전)까지 쓴다. 기술 버튼, 튜토리얼 안내 줄(위쪽일 때), 화면 문구는 그 아래로 옮겼다.
- **일시정지**
  - 화면을 어둡게 하고 가운데에 카드를 띄운다. 카드에는 ‖ 기호, "잠깐 쉬는 중", "화면을 탭하면 3초 뒤 이어서 시작해요", [▶ 이어하기], [목록으로](목록이 있을 때) 버튼이 있다.
  - 화면 아무 곳이나 탭해도 이어하기와 같다.
- **이어하기 카운트다운**: 금색 원형 진행 고리 안에 3·2·1 숫자를 보여 주고, 그 아래 "손가락을 패드에 편하게 올려 두세요"를 띄운다.

## 난이도(초급·중급)와 떨어지기 전 경고 (2026-11-08, 2026-11-09 개정)

### 경과
1. **11-08 첫 요청:** "떨어지기 직전을 슬로우모션, 시작할 때 초급·중급을 고르고 초급만 적용." 0.25배·2초로 만들었다.
2. **이어서:** "0.3초를 3초로, 왜 느려지는지 경고." 0.1배·3초와 아래쪽 경고 카드로 바꿨다.
3. **11-09 사용자 평가:** "느려지긴 했지만 움직이는 것도 느려져서 도움이 전혀 안 된다. 경고라는 느낌도 전혀 없다. 게임하다 바로 알 수 있게."
   - **원인:** 떨어지는 시계와 몸·손발 이동(몸 1.2 m/s, 손발 2.5 m/s)이 같은 판정 틱으로 돌아간다. 시간을 늦추면 고칠 수 있는 동작의 양(0.3초에 몸 36cm)은 그대로이고, 손가락보다 캐릭터가 늦게 따라와 조작만 답답해진다.
   - **결정:** 슬로우모션을 없앴다. 대신 조작은 원래 속도 그대로 두고, 떨어지기까지 버틸 시간만 늘린다. 경고는 진동·소리·화면·캐릭터로 몸이 먼저 느끼게 한다.

### 난이도 고르기
- 난이도를 아직 안 골랐으면 홈에 들어오자마자 고르기 창(초급·중급 카드)이 뜬다.
- 첫 실행이면 고른 뒤 기본 조작 튜토리얼로 간다.
- 홈 오른쪽 위 [난이도] 버튼으로 언제든 바꿀 수 있다.
- 저장 값은 Progress.level(`beginner`/`intermediate`)이다.

### 경고 3단계 (초급·중급 모두, 판정은 바꾸지 않음)
**① 주의 (노랑)** — 미리 알려 주는 단계
- **언제:** 붙어 있는 손발 패드를 누른 순간, 그 손발을 떼면 못 버티는 자세일 때. ClimbSession.release_risk가 몸은 그대로 두고 그 접점만 뺀 힘 계산을 한다. 누른 순간과, 누르고 있는 동안 12틱마다 다시 계산한다.
- **표시:**
  - 그 패드가 노랗게 깜빡이고 "!" 표시가 붙는다.
  - 패드 옆에 "떼면 떨어져요"(버틸 손 없음) 또는 "떼면 위험해요"(힘 균형·문 열림)가 뜬다.
  - 캐릭터 머리 위에 노란 "!"가 뜬다.
- **소리·진동:** "띵" 소리, 짧은 진동.
- **몸통 이동은 따로 경고하지 않는다:** 몸통 끌기는 원래 균형을 깨는 쪽으로 움직이지 않는다(ClimbRules._accept). 위험은 손발을 뗄 때(또는 팔 힘이 다해 미끄러질 때) 생긴다.

**② 위험 (빨강)** — 지지 상태가 "균형 회복 중"(REBALANCING)·"지지 없음"(GRACE)인 동안
- **멈칫:** 들어가는 순간 판정을 0.15초 멈춘다. 신호용이다.
- **소리·진동:** 들어갈 때 경고음과 강한 진동. 그 뒤 0.55초마다 심장 박동처럼 두근(소리·진동) → 0.16초 뒤 두근(더 약하게).
- **화면:**
  - 가장자리가 박동에 맞춰 붉게 뛴다. 위쪽 정보 패널 아래에 그려서 패널은 흐려지지 않는다.
  - 캐릭터 둘레에 남은 예산 고리가 줄어들며 주황 → 빨강으로 바뀐다.
  - 머리 위에 큰 글자가 튀어나온다: 지지 없음 "잡아!", 힘 균형 "균형!", 문 열림 "버텨!".
  - 그 아래에 짧은 이유가 뜬다: "버틸 손이 없어요" / "몸이 지지 밖으로 기울었어요" / "몸이 문처럼 돌아가요". 초급은 남은 초도 함께 보인다.
- **캐릭터:** 겁먹은 표정이 되고, 몸통이 떨린다(남은 시간이 줄수록 세게). 떨어질 때와 달리 고개를 돌려 돌아보지 않는다.
- **지난 문구 대신:** 세션 문구 "균형이 무너지고 있어요"는 띄우지 않는다. 이 경고가 대신한다.

**③ 회복 (초록)** — 떨어지지 않고 위험에서 빠져나온 순간
- 0.8초 동안 초록 빛이 번지고 "휴!"가 뜬다.
- 올라가는 두 음 소리, 약한 진동.

**떨어진 뒤** — 원인 한 줄을 5초 동안 보이고, 처음부터 다시 시작할 때도 이어서 보인다(DangerFeedback.fall_cause). 2.5초 안에 뗀 손발이 있으면 그 손발을 함께 말한다. 지지 없음이면 마지막에 뗀 손을 말한다.

| 상황 | 문구 |
|---|---|
| 팔 힘이 다해 미끄러짐 | "팔 힘이 다 빠져 오른손이 미끄러졌어요. 힘이 줄면 쉬운 자세에서 쉬어 주세요" |
| 지지 없음, 손이 붙어 있었음 | "…잡은 손이 어깨보다 낮아 몸을 버티지 못했어요" |
| 지지 없음, 손이 없었음 | "왼손을 뗀 뒤 몸을 버틸 손이 없었어요. 다른 손을 먼저 잡고 떼 보세요" |
| 문 열림 | "…몸이 문처럼 열려 돌아갔어요. 반대쪽 발로 버텨 보세요" |
| 힘 균형 | "…몸이 손발 지지 밖으로 기울었어요. 몸을 지지 쪽으로 옮겨 보세요" |

### 초급 도움 (중급은 원래 규칙 그대로)
- **버틸 시간 10배:** ClimbRules.imbalance_budget 18틱이 180틱(0.3초 → 3초), grace_budget 9틱이 90틱(0.15초 → 1.5초)이 된다. 몸·손발은 원래 속도로 움직이고, 위험 동안 몸이 지지 쪽으로 저절로 옮겨 가는 회복 동작도 그대로다.
- **해결 안내** (위험 동안)
  - 최근(2.5초 안)에 뗀 손발이 다시 잡을 홀드를 그 손발 색으로 깜빡이고 "다시 잡기"를 띄운다. 그 패드에도 고리와 "이 패드로 다시 잡아요"가 뜬다. 버틸 손이 없을 때는 발보다 손을 안내한다(DangerFeedback.rescue_release).
  - 몸이 기운 경우(지지 없음이 아닐 때)에는 골반에서 지지점 평균 X 쪽으로 초록 화살표와 "몸을 이쪽으로"를 그린다.
- **자동 도움 (위험 게이지 누르기, 2026-11-09)**
  - 사용자 요청: "가운데 동그란 위험 게이지가 다 닳기 전에 누르면 최적의 동작으로 알아서 다음 동작으로. 다리와 팔을 최대 한 번씩. 3번까지, 다 쓰면 경고는 그대로·자동 도움은 만료. 마지막 탑 홀드는 버튼으로 잡지 않게."
  - **누르는 곳:** 위험 동안 캐릭터 둘레 고리(게이지)에 깜빡이는 바깥 테두리와 [눌러서 자동 도움 n/3]이 붙는다. 고리 안 아무 곳이나 누르면 된다(원형 버튼, play_overlay.tap).
  - **고르는 방법 (scripts/climbing/auto_rescue.gd):**
    - 손 하나 옮기기(또는 그대로) × 발 하나 옮기기(또는 그대로)를 모두 따진다. 떨어져 있던 손발을 다시 붙이는 것도 옮기기에 든다.
    - 후보 슬롯은 그 손발이 허용되고, 비어 있고, 관절에서 닿을 만하며, **목표(goal_slots)가 아닌** 것이다.
    - 조합마다 골반 자세를 찾아 판정과 같은 힘 계산으로 버틸 수 있는지(버틸 손 또는 플랫폼, 힘 균형, 문 열림 없음) 본다.
    - 점수가 가장 낮은 것을 고른다.
      - 더하는 항: 손 하중, 부담 큼(STRAINED) 1.0, 옮긴 손발 수 × 0.25, 골반 이동 × 0.8, 허공에 남는 손 0.4·발 0.15
      - 빼는 항: 오른 골반 높이 × 0.6, 지금보다 높은 홀드로 간 손 × 1.0·발 × 0.5
    - 즉 버틸 수 있는 자세 중에서 덜 움직이고, 두 손으로 잡고, 다음 동작으로 한 걸음 나아가는 쪽을 고른다.
    - 계산 시간은 맥에서 25~50ms이며 누를 때 한 번만 계산한다.
  - **움직임:** 0.35초 + 옮기는 손발마다 0.35초에 걸쳐 골반이 옮겨 간다. 손 → 발 순서로 하나씩 살짝 들어 올려 목표 홀드로 옮긴다. 그동안 판정 틱과 떨어지는 시계는 멈추고 패드 입력은 받지 않는다. 끝나면 그 자세로 확정한다(reset_to, 팔 힘은 지금 값 그대로).
  - **못 찾으면:** 마지막으로 안정(STABLE)했던 자세로 되돌린다. 그것도 없으면 "지금은 도울 수 있는 동작이 없어요"를 띄우고 횟수를 쓰지 않는다.
  - **횟수:** 시도마다 3번이다. 다 쓰면 고리 아래에 "자동 도움 끝"만 보이고, 경고는 그대로다. 떨어지거나 다시 시작하면 다시 3번이 된다.
  - **중급:** 버틸 시간이 0.3초라 누를 틈이 없고, 원래 규칙 그대로 둔다(자동 도움 없음).
  - 앞서 만든 [되돌리기] 버튼은 이 기능에 합쳤다.
  - 테스트: tests/test_auto_rescue.gd
    - 네 문제 × 네 위험 상황에서 정상 홀드를 고르지 않는다.
    - 팔·다리를 최대 한 번씩만 옮긴다.
    - 도운 뒤 1초 동안 떨어지지 않는다.
    - 더 높은 홀드에 가산점을 준다.
