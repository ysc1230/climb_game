# 19. 레벨 저작·참조·검수 규약

설계 v0.4 · 2026-10-30 · 실행 데이터 미제작

[07](07_levels.md)의 루트 개요, [09](09_data_and_save.md)의 필드, [16](16_stage_specs.md)의 단계·구간을 레벨 제작자가 같은 규칙으로 채우도록 정리한다. 이번 산출물은 문서이며 엔진 리소스·레벨 파일·검사기 코드를 만들지 않는다. 전 스테이지의 제작 상태는 Draft다.

## 식별자와 좌표

| 대상 | 표기 규칙 | 제약 |
| --- | --- | --- |
| 루트 | T01~T03, R01~R09 | 기존 ID를 유지. 표시 이름과 분리 |
| 일반 손홀드 | H01, H02 등 | 루트 안에서 유일. LH/RH 양손 허용이 기본 |
| 일반 발홀드 | F01, F02 등 | 루트 안에서 유일. LF/RF 양발 허용이 기본 |
| 공용 홀드 | M01, M02 등 | 손/발 슬롯을 별개로 정의. 같은 접점 두 개로 중복 작성하지 않음 |
| 정상 | G01 | goal_left / goal_right 두 슬롯. 각각 LH/RH 모두 허용 |
| 일반 슬롯 | hand_1 / foot_1 | 홀드 안에서 유일, 점유 용량 1 |
| 플랫폼 | P00 시작, P01 중간 휴식 | 시작 플랫폼은 CP로 자동 분류하지 않음 |
| 체크포인트 | CP01 | R06/R09에 각 1개, 각 루트의 P01 참조 |
| CP 전용 홀드 | CP01_HL, CP01_HR, CP01_FL, CP01_FR | 접미사는 저작 위치 설명. 실제 허용 팔다리를 좌우로 제한하지 않음 |
| 튜토리얼 단계 | T01-A 등 16의 ID | 실패/다음 참조가 존재해야 함. 의도된 재시도 순환만 허용 |
| 에셋 | 14의 ID + 변형 번호 | 예: HD01_01. 표시명이나 파일명으로 참조하지 않음 |

전체 슬롯 키는 `R01/H01/hand_1`처럼 루트/홀드/슬롯의 조합으로 표기한다. 대소문자를 구별하고 공백·슬래시는 개별 ID 안에 쓰지 않는다. 다른 루트가 같은 H01을 사용해도 전체 키는 다르다. 삭제한 ID를 다른 역할에 재사용하지 않는다.

월드는 m, X 오른쪽/Y 위이며 Z는 외형을 위한 깊이다. 홀드 인스턴스의 이동·회전을 슬롯의 로컬 앵커에 적용한 결과가 최종 월드 접점이다. 07의 R01 표는 최종 월드 접점이다. G01은 원점 (0,3.0)에 로컬 앵커 (-0.22,0), (+0.22,0)을 두면 표와 일치한다. 둘 모두 월드 좌표를 로컬 값처럼 더해 높이가 두 배가 되지 않게 한다.

발 지지 방향은 평면의 단위벡터로 정의한다. 기본 (0,1), 허용각 60°를 사용한다. 경사 발판을 추가하면 시각적 면과 지지 방향을 함께 바꾸되 기존 루트의 규칙을 몰래 바꾸지 않는다. 시작/CP 접점은 다른 말단과 중복 점유하지 않는다.

## 시작·체크포인트의 명시적 연결

아래는 이미 정한 자세를 ID에 연결하는 저작 초안이다. 표의 ± 좌표는 왼쪽 음수·오른쪽 양수다. 골반 회전은 0°, 속도 0, 손 피로 100이다.

| 위치 | 플랫폼·상단 | 골반 | 손 접점 | 발 접점 |
| --- | --- | --- | --- | --- |
| R01 시작 | P00, Y=0.10 | (0,0.95) | H01/H02: (±0.45,1.80) | F01/F02: (±0.30,0.10) |
| R06 CP01 | P01, Y=4.20 | (0,5.05) | CP01_HL/HR: (±0.45,5.90) | CP01_FL/FR: (±0.30,4.20) |
| R09 CP01 | P01, Y=5.00 | (0,5.85) | CP01_HL/HR: (±0.45,6.70) | CP01_FL/FR: (±0.30,5.00) |

R01의 P00.foot_slot_keys는 R01/F01/foot_1, R01/F02/foot_1이다. CP 플랫폼은 해당 루트의 CP01_FL/foot_1, CP01_FR/foot_1을 가리킨다. CP 복귀는 LH→CP01_HL/hand_1, RH→CP01_HR/hand_1, LF→CP01_FL/foot_1, RF→CP01_FR/foot_1로 지정한다. required_content_version은 해당 루트의 버전과 같아야 한다.

플랫폼의 가로 범위는 X=-0.65~+0.65m를 초기안으로 한다. 발 슬롯이 범위 안에 있다는 사실만으로 플랫폼 지지가 되지는 않는다. 지정된 두 발 슬롯의 점유·하중 지지와 골반 위치 조건을 04대로 만족해야 한다. 다른 일반 루트의 시작 자세도 같은 높이의 시작 템플릿을 제안하되, 좌표 작성과 충돌 검수가 끝나기 전에는 실제 배치로 확정하지 않는다. 튜토리얼은 단계별 시작 자세를 별도로 작성한다.

일반 루트의 실패선 초안은 Y=-0.50m다. 벽 높이와 무관하게 시작 바닥 아래에 둔다. 추락 후 실패선 도달 또는 최대 1초 연출 중 먼저 충족한 조건으로 실패하므로 높은 벽에서 긴 자유낙하를 기다리지 않는다. 튜토리얼의 의도된 추락은 16의 안전 재설정을 우선한다.

## 시작 자세의 정적 산술 확인

R01 시작과 위 두 CP는 같은 자세를 수직 이동한 것이다. 04의 어깨 오프셋 (±0.20,+0.55), 골반의 고관절 (±0.14,0), 팔 길이 0.40+0.38m, 다리 길이 0.52+0.48m를 대입한 결과다. 소수 표시는 반올림했으며 계산에는 원래 값을 사용했다.

| 확인 항목 | 산술 결과 | 문서 제한과의 관계 |
| --- | --- | --- |
| 어깨→손 | √(0.25²+0.30²) = 0.390512m | 팔 도달 0.20~0.78m 안 |
| 고관절→발 | √(0.16²+0.85²) = 0.864928m | 다리 길이 범위 안 |
| 팔꿈치 굽힘 | 약 119.978° | 5~155° 안 |
| 무릎 굽힘 | 약 60.304° | 5~145° 안 |
| 발 지지 방향과 고관절 방향의 각 | 약 10.660° | 60° 안 |
| 발보다 높은 고관절 | 0.85m | 최소 0.05m 이상 |
| 골반 X | 0 | 두 발 X 사이, 플랫폼 가로 범위 안 |

두 뼈의 굽힘각은 완전히 편 상태를 0°로 한다. 위 표는 길이·각도·기본 지지 조건의 산술 확인이다. 메시 충돌, 팔꿈치 방향, 자세 보정의 수렴, 이동 경로, 피로, 카메라, 실제 재시작을 검증하지 않았다. 전체 초기 자세 검수가 끝나지 않았으므로 이 계산만으로 GeometryChecked로 올리지 않는다.

## 레벨 한 개를 작성할 때 남길 제작표

| 구역 | 작성 내용 | 문서 단계에서 판별할 것 |
| --- | --- | --- |
| 식별 | route_id, content_version, 작성 상태, 담당 역할 | ID·버전·표시명 분리 |
| 목적 | 한 문장 학습 목표, 처음 등장하는 동작 | 16의 난이도 순서와 일치 |
| 공간 | bounds, 실패선, 정상 높이, 플레이 시야 | 슬롯이 벽 범위 안, 정상 접근 공간 확보 |
| 접점 | 홀드·슬롯·종류·월드 좌표·허용 팔다리 | 모든 키 유일, capacity=1, 시각 앵커와 구분 |
| 안전 자세 | 시작 및 CP의 네 접점·골반·회전 | 참조 존재, 좌우 배정, 버전 일치 |
| 구간 | 도입→주 과제→회복→마무리 | 새 규칙을 한꺼번에 넣지 않음 |
| 의도 경로 | 이동할 말단·출발/도착 키·남는 손/발 | 적어도 한 손 또는 플랫폼 지지 유지 계획 |
| 대안/힌트 | 선택 가능한 다른 경로·힌트 1/2단계 | 숨은 막다른 길·자동 이동과 구분 |
| 기록 | 예상 이동 수·시간 메달·CP 여부 | 16의 예산과 차이 및 이유 |
| 검증 이력 | 문서 검토와 실행 증거를 별도 칸으로 기록 | 빈 실행 증거를 “통과”로 표시하지 않음 |

의도 경로의 각 행은 이동 전 4개 슬롯, 이동할 말단, 도착 슬롯, 남는 지지, 이동 후 기대 자세, 피로 위험을 기록한다. “H03 다음 H04”만 적으면 어느 손을 놓는지와 다른 접점의 제약을 확인할 수 없다. 같은 시점에 두 말단을 옮기는 행은 두 요청과 남는 지지를 함께 적는다.

## 이후 사용할 검수 기준

문서 검수에서는 ID 중복, 없는 슬롯 참조, 잘못된 허용 팔다리, 정상 슬롯 수, 플랫폼 발 슬롯 수, 버전 연결, 좌표 단위, 12개 루트의 예산 일관성을 확인한다. 아직 작성하지 않은 좌표는 오류 없이 통과한 데이터로 취급하지 않는다.

GeometryChecked는 완성된 배치의 모든 시작/CP·경로 자세에 대한 정적 제약 확인, Played는 실제 의도 경로 완등, Tuned는 시간·피로·난이도 조정, Ready는 지정 기기 증거와 필수 시험을 갖춘 상태다. 해당 단계의 작업은 현재 제외된 후속 개발·실행 검증 범위다.

슬롯 이동·허용 종류·CP 자세·목표·기록에 영향을 주는 배치 변경은 content_version을 올린다. 피로·도달·몸통 조정값 변경은 tuning_version을 올린다. 단순 오탈자·파일 정리는 플레이 규칙이 같다면 콘텐츠 버전을 바꾸지 않는다. 오래된 완료 기록과 새 버전을 비교하는 방식은 09를 따른다.
