# 23. 개발 착수 검토·수정된 개발 순서

2026-10-30(KST) · 설계 v0.4 기준 · 개발 착수

설계 v0.4 전체를 개발 관점에서 검토하고, R01 좌표를 04 규칙으로 간이 계산했다. 이 문서의 개발 순서는 [11](11_roadmap_and_backlog.md)의 M1~M3 순서보다 우선한다. 작업 ID(B01~B30)와 게이트(G0~G5)는 그대로 쓴다.

## R01 정적 계산 결과

`tools/r01_static_check.py`는 04의 팔·다리 길이, 관절 제한, 발 지지 조건, 목표 자세 비용, 27후보·8라운드 근방 탐색을 그대로 옮긴 계산이다. 속도·가속도 제한과 충돌은 생략하고 각 단계의 수렴 자세만 비교했다. **게임 실행 결과가 아니다.**

| 관찰 | 값 | 영향 |
| --- | --- | --- |
| 시작 자세가 비용 최소 자세가 아님 | 문서 골반 Y 0.95 → 수렴 0.83 | 시작 직후 12cm 처짐 |
| 첫 이동 LH→H03 | 뗀 직후 거리 0.782m, 팔 최대 0.779m | 몸이 움직인 뒤에야 닿는 경계값 |
| 마지막 이동 LH→G01 | 몸통이 X=+0.40m로 쏠림, 거리 0.83~0.97m | **잡기 불가.** RH 먼저면 가능 |
| 비용 지형 (H05/H06/F05/F06) | 중앙 0.20, 좌우 ±0.38m에 최소 0.12 | 좌우 쌍안정, 이동 순서에 따라 쏠림 |
| 좌우 정렬 가중치 0.4 / 1.0 | 첫 이동 LH→H03부터 막힘 | 가중치 하나로 해결 안 됨 |

16의 R01 수락 조건 "좌우 어느 손부터 시작해도 의도 경로 성립"에 어긋난다. 홀드 좌표는 손 계산이 아니라 자세 계산기의 수렴 자세를 기준으로 다시 저작해야 한다. 1B 단계에서 경로 검증기로 처리한다.

## 재검토할 설계 (G1/G2에서 확정)

| 우선 | 항목 | 문제 | 제안 시작값·조치 |
| --- | --- | --- | --- |
| 1 | drag_deadzone | 10논리 단위 ≈ 0.8mm, Android 기본 touch slop 8dp ≈ 1.3mm보다 작음 | 물리 단위로 정의, 2~3mm에서 시작 |
| 2 | release 순간 밀림 | 후보 반경 0.12m ≈ 손가락 1.5mm, 히스테리시스 0.03m ≈ 0.4mm | release 직전 50~80ms 이동 무시 규칙 검토 |
| 3 | 홀드 가독성 | 시야 높이 3.8m → 1m ≈ 18mm, 0.15m 홀드 ≈ 2.7mm | 회색 박스로 기기 확인, 필요 시 시야 3.0~3.2m |
| 4 | 2D 판정 ↔ 3D 깊이 | 골반 Z 오프셋 때문에 3D 팔다리 길이 = √(2D 거리²+Z²), 최대 도달에서 모델 길이 부족 | 신장도에 따라 골반 Z를 줄이는 규칙, 20의 리그 검토 포즈에 최대 도달 추가 |
| 5 | 자세 비용 함수 | 처지는 성향(선호 팔 0.52m)과 좌우 쌍안정 | 1B에서 헤드리스로 조정, 04 갱신 |

수치 변경은 위 검증 후 04에 반영한다. 이 표의 시작값은 제안이며 측정 결과가 아니다.

Python 간이 계산(`tools/r01_static_check.py`)은 손을 떼는 즉시 잡는다고 가정해 낙관적이었다. 이후 기준은 GDScript 검증기다.

실행 방법:

```
godot --headless --path game --script res://tests/run_tests.gd
godot --headless --path game --script res://tools/route_check.gd -- R01
```
