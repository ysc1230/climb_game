# 28. 일반·기술 모드, 등급 문제, 기술 과정 설계

설계 v0.7 초안 · 2026-11-01(KST) · 구현 전 · 브랜치 `design/modes-grades`

## 1. 목적

시작 화면에 **일반**과 **기술** 두 탭을 둔다.

- **일반:** V0부터 등급을 골라 그 등급의 여러 문제를 푼다.
- **기술:** 기술마다 튜토리얼과 난이도별 문제를 푼다. 튜토리얼을 깨면 일반 모드에서 그 기술 버튼을 쓸 수 있다.

난이도는 두 가지에서 나온다(사용자 결정).

1. **기술을 알아야 풀린다.** 그 기술 없이는 손이 닿지 않거나 몸이 돌아가 떨어진다.
2. **손이 정확해야 풀린다.** 홀드가 작아 중앙을 잡기 어렵고, 먼 거리를 탄력으로 잡아야 하고, 체력을 아껴야 한다.

같은 기회에 **기본 조작과 겹치는 기술 버튼을 정리한다**(3장).

## 2. 사용자가 정한 것

- 기본 조작(패드)으로 할 수 있는 기술은 버튼에서 뺀다. 하이스텝·락오프가 그 예다. 나머지도 설계자가 판단해 뺀다.
- 시작하면 일반/기술 탭. 일반은 V0부터 등급을 고르고, 등급마다 여러 문제가 있다. 기술은 기술마다 튜토리얼과 여러 난이도 문제가 있다.
- 난이도는 "기술 없이는 불가능" + "숙련도가 낮으면 홀드를 못 잡음"으로 만든다.
- **능력치 성장은 넣지 않는다.** 기술 과정을 깨면 능력치가 오르는 대신 **그 기술 버튼이 일반 모드에서 해금**된다. 모든 플레이어의 신체 조건은 같다(01/02/27 유지).
- 나중에 바꿀 수 있도록 이 작업은 별도 브랜치에서 한다.

## 3. 목표가 아닌 것과 실패로 볼 것

- 기술 과정 반복으로 일반 문제가 쉬워지면 실패다. 해금은 "쓸 수 있게 됨"이지 "세짐"이 아니다.
- 같은 등급 문제인데 어떤 것은 V0 수준이고 어떤 것은 V4 수준이면 실패다. 등급마다 4장의 기준과 7장의 검증을 통과해야 한다.
- 필요한 기술 버튼이 잠긴 채로 일반 문제를 시작하게 해서 이유 없이 막히게 하면 실패다.
- 게임이 홀드 순서를 정해 주거나 자동으로 오르면 실패다(27 §3 유지). 튜토리얼도 "어느 팔다리, 어느 홀드"까지만 안내하고 대신 움직이지 않는다.
- 실행할 때 무작위로 문제를 만드는 기능은 넣지 않는다(07 유지). 문제는 모두 데이터로 만들고 검증한다.
- 오버행(기울어진 벽)은 넣지 않는다. 벽은 지금처럼 수직 평면 하나다. 난이도는 홀드 배치·크기·방향·기술로 만든다.

## 4. 기술 정리

### 4.1 기준

**버튼은 패드(평면 드래그)로 표현할 수 없는 동작만 남긴다.** 엉덩이 돌리기(yaw), 벽 쪽·바깥쪽 깊이로 교차, 홀드에 발을 거는 것, 홀드 없는 벽을 딛는 것이 여기에 해당한다. 위치만 다른 기술은 패드로 하고, 게임은 그 동작을 판정해 기록한다.

### 4.2 결과

| 기술 | 결정 | 근거(현재 코드) | 기술 탭 |
| --- | --- | --- | --- |
| 하이스텝 → 일어서기 | 버튼 삭제 | 패드로 발을 고관절−0.20m 이상에 두면 MoveClassifier가 HighStep → StandUp(골반을 그 발 위로)으로 처리 | 패드 기술 과정 |
| 락오프 | 버튼 삭제 | 패드로 닿지 않는 위로 뻗으면 반대 팔이 자동으로 LockOff 선호(0.42) | 패드 기술 과정 |
| 휴식 | 버튼 삭제 | 놓은 손은 이미 +15/s 회복, 입력이 없으면 이미 Rest 자세(팔 0.70·다리 0.86) | 기본 조작 과정에 "쉬는 법" 단계로 포함 |
| 크로스 | 버튼 삭제 | 패드로 반대 손 너머를 잡으면 CrossReach로 같은 판정 | 패드 기술 과정 |
| 매치 | 버튼 삭제 | 패드로 반대 손이 잡은 홀드의 빈 구간을 잡으면 같은 판정(합손 포함) | 패드 기술 과정 |
| 풋스왑 | 버튼 삭제 | 패드 풋스왑 구현됨(Ruling 14) | 패드 기술 과정 |
| 인사이드 엣지 | 버튼 삭제 | 패드로 디디면 기본이 inside, yaw 0 복귀 | 기본 조작 과정 |
| 데드포인트 | 버튼 삭제 | 패드 빠른 드래그(≥1.0m/s, 상승 창)로 이미 발동. 버튼 흐름은 보너스가 0.05m뿐이라 쓸 이유가 없음 | 패드 기술 과정 |
| 사이드풀·개스턴·언더클링 | 버튼 삭제, **패드 잡기 방향 자동 선택** 추가(4.3) | 실제로는 홀드 모양과 몸 위치가 잡는 방향을 정한다 | 패드 기술 과정 "방향 홀드" |
| 아웃사이드 엣지 | **버튼 유지** | 엉덩이를 ±30° 돌림, 패드로 표현 불가 | 버튼 기술 과정 |
| 드롭니 | **버튼 유지** | 발 회전·무릎 내림·엉덩이 ±35°, 패드로 표현 불가 | 버튼 기술 과정 |
| 플래그 3종 | 버튼 삭제. 인사이드·아웃사이드 플래그는 기술에서 뺀다 | 패드로 발을 허공에 놓으면 이미 "균형 발"(25 MV06, Flag 상태)이 되고 버튼과 같은 균형 비용(flag_cost)으로 같은 효과를 낸다. 인사이드·아웃사이드는 깊이 값이 화면 표현에만 쓰여 판정이 같은 쪽 플래그와 똑같다(technique_judge FLAG_DEPTH) | 패드 기술 과정 "플래그" |
| 힐훅·토훅·스미어링 | 버튼 유지(2차, 미구현) | 걸기·벽면 딛기는 패드로 표현 불가 | 2차 구현 때 과정 추가 |

남는 버튼은 1차 **2개**(아웃사이드 엣지, 드롭니)다. 기술 패널은 묶음 없이 버튼 목록 하나로 둔다. 인사이드·아웃사이드 플래그는 나중에 서로 다른 물리 효과(예: 엉덩이 회전 허용 범위)를 설계할 때 다시 검토한다.

삭제한 버튼의 판단·실행 코드 중 패드 동작이 쓰는 부분(패드 데드포인트, 패드 풋스왑, 합손 이동, 균형 발의 flag_cost)은 남기고, 버튼 전용 경로만 지운다. techniques.json은 기술 탭 설명 데이터로 계속 쓰므로 항목을 지우지 않고 `"input": "button" | "pad"`를 더한다.

### 4.3 패드 잡기 방향 자동 선택

패드로 손을 놓아 잡을 때, 홀드의 grip_modes 중 **지금 자세에서 지지 계산이 가장 좋은 방식**을 고른다.

1. 그 홀드의 각 grip_mode로 접점을 만들어 SupportSolver로 지지 비용(27 §7의 균형 비용과 같은 값)을 계산한다.
2. 성립하는(힘 균형이 풀리는) 방식 중 비용이 가장 작은 것을 쓴다. 비용 차이가 0.02 미만이면 목록의 앞쪽 방식을 쓴다(떨림 방지).
3. 어느 방식도 성립하지 않으면 지금처럼 grip_modes[0]으로 잡고 기존 규칙(불균형 → 추락 판정)을 따른다.
4. 기존 조건은 그대로 둔다. 언더클링은 홀드가 어깨 아래이고 하중 받는 발이 높아야 힘을 쓰고, 사이드풀·개스턴은 q ≥ 0.5여야 한다(27 §8.1). 조건을 못 맞추면 그 방식은 성립하지 않는 것으로 본다.
5. 고른 방식은 접점에 기록하고 기술 로그에 `pad_grip` 이벤트로 남긴다(튜토리얼 판정용).

잡은 뒤 몸이 움직여 다른 방식이 더 좋아져도 바꾸지 않는다. 다시 잡아야 바뀐다(실제로도 손을 고쳐 잡는다).

## 5. 화면 구조

### 5.1 흐름

```mermaid
flowchart TD
    Boot[실행] --> First{첫 실행인가}
    First -->|예| Basic[기본 조작 튜토리얼]
    Basic -->|완료 또는 건너뛰기| Home
    First -->|아니오| Home[홈: 일반 | 기술 탭]
    Home -->|일반| Grade[등급 선택 V0~]
    Grade --> Problems[그 등급 문제 목록]
    Problems --> Play[플레이]
    Home -->|기술| Courses[기술 과정 목록]
    Courses --> Course[과정: 설명·튜토리얼·문제]
    Course --> Play
    Play --> Result[완등 또는 실패]
    Result --> Problems
    Result --> Course
```

### 5.2 홈

- 상단에 탭 두 개: **일반**, **기술**. 마지막으로 연 탭을 기억한다. 첫 실행 직후는 일반 탭(V0이 열린 것이 보이게).
- 패드 맞추기·설정·색상 선택 화면은 아직 없다. 1차에서도 만들지 않는다. 패드 배치는 지금 플레이 화면의 고정 배치를 쓴다. 이 화면들은 05/18 설계대로 후속 차수에서 만든다. 색상 해금 조건(18의 R03·R09 완등)은 그때 등급 기준으로 바꾼다.

### 5.3 일반 탭

- 위: 등급 줄(V0, V1, V2 …). 열린 등급, 잠긴 등급(자물쇠와 여는 조건), 완료 개수(예: 3/4)를 보여 준다.
- 아래: 고른 등급의 문제 카드. 카드에는 이름, **필요 기술 아이콘**, 메달(완등·무추락·시간)을 보여 준다.
- 필요한 버튼 기술이 아직 잠겨 있으면 카드는 잠기고 "드롭니를 배우면 열려요"와 **[배우러 가기]**(그 기술 과정으로 이동)를 보여 준다.
- 패드 기술은 해금이 필요 없으므로 아이콘만 보여 준다(어떤 기술을 쓰는지 알려 주는 정보).

### 5.4 기술 탭

- 과정 카드 목록(6장 순서). 카드에는 이름, 종류(**버튼 기술 / 패드 기술**), 진행(튜토리얼 ✓, 문제 2/3), 버튼 기술은 해금 여부를 보여 준다.
- 과정 화면: techniques.json의 목적(purpose_ko)·쓰는 때(when_ko)·방법(how_ko) 짧게, 그 아래 튜토리얼 1개 + 문제 3개(쉬움·보통·어려움). 문제는 앞 단계를 깨야 열린다.

### 5.5 플레이 중 기술 패널

- 일반 문제: **해금된 버튼 기술만** 보여 준다. 해금된 것이 없으면 기술 버튼 자체를 숨긴다(V0–V1은 버튼 없이 진행).
- 기술 과정 튜토리얼: **그 과정의 기술만** 보여 준다(처음 배우는 사람이 헷갈리지 않게).
- 기술 과정 문제: 그 과정의 기술 + 이미 해금된 기술.

- C_FLAG
- C_OUTSIDE_EDGE, C_DROP_KNEE(버튼 기술)
- C_FOOT_SWAP, C_LOCK_OFF, C_DIRECTION
- 2차 버튼(힐훅·토훅·스미어링)

**재구성에 따라 바뀌는 것**
- **1차에는 버튼 기술 과정이 없다.** 그래서 버튼 기술(아웃사이드 엣지·드롭니)을 해금할 수 없고, 일반 모드 1차 문제는 기술 버튼 없이 진행한다. 기술 버튼은 해금된 것이 없으면 숨긴다(5.5). 버튼 기술의 판단·실행 코드는 그대로 둔다.
- 일반 등급 기준(7.3)의 1차 기술 범위가 바뀐다.
  - V1: 다리 내리기·핸드매치·크로스 중 하나
  - V2: 패드 기술 2종(버튼 기술 대신, 데드포인트는 2026-11-05 제거)
- C_BASIC은 사용자 문구대로 "손과 발을 하나씩 옮겨 잡기"에 집중하도록 다시 만든다. 지금 C_BASIC_T에 있는 두 팔다리 함께 움직이기, 일부러 떨어져 보기, 쉬는 법 단계는 뺀다(16의 T01~T03 전체 이식을 대체한다).

### 6.1 튜토리얼 구조

튜토리얼은 **단계 목록**이다. 단계마다 한 문장 안내, 목표 이벤트, 막힘 도움말을 가진다(16의 튜토리얼 규칙 확장).

1. **보기(2026-11-04 변경):** 멈춤은 없다(사용자 결정). 단계는 바로 시작한다. 안내 줄에 한 문장 설명이 나오고, 목표 홀드는 단계 내내 **계속 반짝인다**(밝기·크기 약 1.4Hz). 표시는 안내 줄보다 위에 그려 가려지지 않는다. 안내 줄은 진한 바탕(불투명도 0.94)·밝은 테두리·큰 글자(28)로 그린다. 목표 홀드가 화면 위쪽 절반에 있으면 화면 아래 가운데로 내려가 그 홀드를 덮지 않는다.
2. **해 보기:** 그 기술을 실행할 수 있는 자세에서 시작한다. 목표 이벤트(위 표)가 나오면 다음 단계.
3. **써먹기:** 그 기술을 써야만 닿는 홀드 하나를 잡는다. 기술 없이 잡으려 하면 거부 이유와 함께 "드롭니를 먼저 해 보세요"를 보여 준다.

막힘 처리는 16과 같다. 12초 동안 목표 이벤트가 없거나 같은 단계에서 3번 실패하면 도움말 버튼을 강조한다. 도움말은 1단계 "움직일 팔다리", 2단계 "누를 버튼과 홀드" 순이다. 대신 움직여 주지 않는다. 튜토리얼에서 떨어지면 그 단계 시작 자세로 돌아간다(처음부터가 아님). 단, 목표 이벤트가 추락인 단계(C_BASIC의 지지 잃기 체험)는 추락이 곧 완료이고, 완료 후 다음 단계 시작 자세로 간다.

단계마다 규칙을 바꿀 수 있다(8.1 `rules`). 피로 감소 끄기, 시작 체력, 시작 자세, 그 단계에서 보이는 기술 버튼이 여기에 해당한다. 이 규칙은 튜토리얼에서만 쓰고 기록·메달에 영향을 주지 않는다(튜토리얼은 메달이 없다).

### 6.2 과정 문제

> **2026-11-04 대체:** 쉬움·보통·어려움 3문제는 과정마다 **20단계**로 바뀌었다([30](30_technique_20_levels_design.md)). 아래 세 줄은 이전 설계 기록이다.

- **쉬움:** 그 기술을 한 번 쓰는 짧은 문제(이동 6~10번). 기술 쓸 곳이 하나뿐이다.
- **보통:** 그 기술을 두 번 이상, 좌우를 바꿔 쓴다. 홀드가 조금 작다.
- **어려움:** 그 기술 + 이미 배운 다른 기술 하나를 잇는다. 해당 기술이 V3 수준 이상에서 쓰이는 배치다.

과정 문제의 등급 표시는 일반 등급과 같은 기준으로 매겨서 보여 준다(예: "드롭니 · 어려움 · V3"). 이렇게 하면 플레이어가 일반 모드 어느 등급에서 이 기술이 필요한지 알 수 있다.

## 7. 일반 모드 등급

### 7.1 등급 범위와 문제 수

- 1차: V0~V2, 등급마다 **4문제**. 2차: V3~V5, 등급마다 4문제. 3차 이후 V6 이상과 등급별 추가 문제.
- 1차 문제는 1차 과정에서 가르치는 기술만 필요로 한다. V1은 하이스텝·크로스·플래그 중 하나, V2는 아웃사이드 엣지·드롭니 중 하나다.
- 기존 R01은 V0의 첫 문제(G_V0_01)가 된다. 07의 R02~R09 계획(데이터 없음)은 이 등급 문제로 대체한다. 07의 학습 요소(지그재그, 옆 이동, 잠깐 버티기 등)는 V0~V1 문제 주제로 쓴다.

### 7.2 해금

- V0: 기본 조작 과정 튜토리얼을 깨면 열린다(건너뛰기 가능, 건너뛰어도 열림 — 07의 기존 규칙과 같다).
- V(n+1): V(n)의 문제 중 **2개**를 완등하면 열린다.
- 열린 등급 안의 문제는 순서 없이 고를 수 있다. 단, 필요 버튼 기술이 잠긴 문제는 5.3처럼 잠긴다.
- 해금 상태는 저장하지 않고 완등 기록에서 매번 계산한다(9장).

### 7.3 등급 기준(초기값, 플레이 후 조정)

"도달 여유"는 잡는 순간 그 팔다리가 더 뻗을 수 있었던 거리다(검증 봇이 측정, 7.4). "필요 기술"은 그 기술 없이는 해당 구간을 못 지나간다는 뜻이다(7.4의 기술 없이 재생 검사로 확인).

| 등급 | 필요 기술 | 손홀드 반폭(hand_area.half_width) | 도달 여유(가장 어려운 이동) | 발판 | 기타 |
| --- | --- | --- | --- | --- | --- |
| V0 | 없음(패드 기본) | ≥ 0.12m | ≥ 0.15m | 손 이동마다 가까운 발판 | 이동 8~14번, 위로 곧게 |
| V1 | 패드 기술 1종(하이스텝·크로스·플래그 중, 2차부터 매치·풋스왑 추가) | ≥ 0.10m | ≥ 0.10m | 대부분 가까움 | 좌우·대각 이동 |
| V2 | 버튼 기술 1종 1회(아웃사이드 엣지·드롭니 중) | ≥ 0.08m, 방향 홀드 일부 | ≥ 0.06m | 핵심 구간은 발판이 멀거나 한쪽뿐 | |
| V3 | 버튼 기술 1종 2회 이상 | ≥ 0.06m | ≥ 0.03m | 드묾 | 락오프 구간 |
| V4 | 기술 2종 이상 연결 | 0.05m 홀드 연속 구간 | ≥ 0.02m | 드묾, 작은 발판 | 한 손 버티는 구간(피로 관리) |
| V5 | 기술 3종 이상 | 0.04m 홀드 포함 | ≥ 0.0m | 매우 드묾 | 긴 루트, 피로 관리 필수 |

손홀드가 작으면 정확하게 놓지 않을 때 끝을 잡게 되고(q 낮음) 힘 범위·피로가 나빠진다(27 §8.1). 이것이 "숙련도가 낮으면 못 잡는" 축이다. 판정 반경이나 규칙을 등급마다 바꾸지 않는다. 같은 규칙에서 홀드 크기와 배치만 바꾼다.

### 7.4 검증(문제마다 필수)

RouteBot을 확장한다.

1. **의도 경로 재생:** intended_moves에 기술 단계를 넣을 수 있게 한다. 형식 `["LF", "T_DROP_KNEE"]`(그 자리 기술), `["LF", "T_OUTSIDE_EDGE", "<slot key>"]`(홀드로 옮기는 기술). (`["RH", "<slot key>", "deadpoint"]` 형식은 2026-11-05 데드포인트 제거로 없앴고 검증에서 오류다.) 의도 경로가 완등해야 한다. 지금처럼 좌우 손 순서를 바꾼 재생도 가능한 경우 확인한다.
2. **기술 없이 재생:** required_techniques의 기술마다 봇에서 그 기술을 **금지**하고 같은 의도 경로를 재생한다. 그 기술을 쓰는 단계의 바로 다음 이동이 **실패**해야 한다. 실패하지 않으면 그 기술은 "필요"가 아니므로 등급·태그를 고친다. 금지 방법:

   | 기술 | 봇에서 금지하는 것 |
   | --- | --- |
   | 버튼 기술(아웃사이드 엣지·드롭니) | 그 기술 단계를 건너뛰고, 홀드로 옮기는 기술은 같은 홀드를 패드로 딛는다 |
   | 하이스텝 | 고관절−0.20m보다 높은 발 목표를 거부하고 StandUp 선호(다리 0.86·골반을 발 위로)를 끈다 |
   | 크로스 | 반대 손 X를 넘는 손 목표를 거부한다 |
   | 플래그 | 놓은 발의 Flag 상태를 끈다(발은 Free, 균형 비용에 쓰지 않음) |
   | 매치 | 반대 손이 잡은 홀드를 거부한다 |
   | 풋스왑 | 패드 풋스왑을 끈다 |
   | 락오프 | LockOff 선호(팔 0.42)를 끄고 뻗기 선호(0.60)를 쓴다 |
   | 방향 홀드 | 잡기 방향 자동 선택을 끄고 grip_modes[0]만 쓴다 |

   이 검사는 "의도 경로의 그 지점에서 그 기술 없이는 다음 이동이 안 된다"는 **국소 검사**다. 다른 순서로 돌아가는 길까지 모두 막혔다는 증명은 아니다. 다른 길은 기기 플레이 검증에서 확인하고, 발견되면 홀드를 고친다.
3. **측정값 기록:** 가장 작은 도달 여유, 가장 작은 손 반폭, 최대 손 하중, 최소 체력, 이동 수, 시뮬레이션 시간. 7.3 표와 비교해 벗어나면 경고한다(경고는 실패가 아니다. 사람이 등급을 다시 본다).
4. 기존 정적 검사(09 로드 전 불변 조건)와 route_check의 출력에 위 결과를 더한다. 모든 문제 데이터는 테스트에서 한 번씩 검증한다.

봇 통과는 "시뮬레이션상 가능"이다. 기기 플레이 전까지 문제는 Draft다(07 유지).

기술별 사용 조건, 기술이 꼭 필요하게 만드는 배치, 등급별 사용 위치, 제작·검증 절차는 [29](29_technique_conditions_and_authoring.md)를 따른다. 위 표의 도달 여유 하한은 29 §4의 값(잡은 뒤 안정 자세 기준)으로 바뀌었다.

## 9. 저장

지금은 저장 코드가 없다. 09의 저장 구조를 따르는 첫 구현을 이번 범위에 넣는다.

| 영역 | 이번에 저장하는 것 |
| --- | --- |
| 메타데이터 | schema_version=1, 저장 일련번호, 앱 버전 |
| 진행 | 완등한 route_id 집합(content_version 포함), 깬 튜토리얼 집합, **기본 조작 건너뜀 여부**, 마지막으로 연 탭 |
| 기록 | route_id/content_version별 메달(완등·무추락·시간)과 최고 시간 |

설정 화면이 없으므로 설정은 저장하지 않는다. "첫 실행"은 C_BASIC을 깼거나 건너뛴 기록이 없는 상태다. 해금(등급, 버튼 기술, 과정, 과정 문제 잠금)은 **진행 기록에서 계산**하고 따로 저장하지 않는다. 그래야 규칙을 바꿔도 저장을 고칠 필요가 없다. 저장은 `user://save.json`에 임시 파일로 쓴 뒤 이름을 바꿔 원자적으로 저장한다(09 저장 원자성). 재개(중단한 시도 이어하기)·보조 기록 구분은 이번 범위에서 빼고 09의 후속으로 둔다.

1차 문제 수(재구성 뒤): 튜토리얼 5 + 과정 4개 × 20단계 = 85, 일반 V0~V2. 20단계 제작 방식은 30 §9 시범으로 정한다. 문제는 개발 중에 데이터로 직접 만들고 7.4 검증을 통과한 것만 넣는다.

## 12. 설계자 판단(사용자가 확인할 것)

- **플래그 버튼 3종도 없앤다.** 패드 균형 발과 효과가 같고, 인사이드·아웃사이드는 판정이 같아서다(4.2). 남는 버튼은 아웃사이드 엣지·드롭니 2개.
- 사이드풀·개스턴·언더클링 버튼을 없애고 패드 잡기 방향을 자동으로 고른다(4.3).
- 버튼 기술 해금 단위는 **튜토리얼 완료**다(과정 문제까지 깰 필요 없음).
- 다음 등급은 이전 등급 **4문제 중 2개** 완등으로 열린다.
- 과정끼리는 잠그지 않는다. 기본 조작을 깨거나 건너뛰면 V0과 모든 과정이 열린다.
- 등급별 수치(7.3)는 초기값이며 플레이 후 조정한다.
- 1차는 V0~V2, 기본 조작, 하이스텝·크로스·플래그·아웃사이드 엣지·드롭니 과정까지다.
- 기본 조작은 기존 T01~T03 단계와 규칙을 그대로 옮긴 튜토리얼 하나다(문제 없음).
- 튜토리얼에서 떨어지면 그 단계 시작으로 돌아간다(추락이 목표인 단계 제외).
- 패드 맞추기·설정·색상 화면은 1차에 넣지 않는다.
- "기술 없이 재생" 검사는 국소 검사다(7.4).

## 13. 구현자에게 맡기는 것

- 화면의 시각 디자인(등급 줄·카드 모양, 아이콘). 색만으로 잠금·완료를 구분하지 않는다(05).
- 문제 좌표 자체. 단 7.3 기준과 7.4 검증을 지킨다.
- 튜토리얼 강조 연출.
- 삭제한 버튼 코드 정리 범위(4.2의 "패드 동작이 쓰는 부분은 남김"을 지키는 한).
