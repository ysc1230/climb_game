# 47. 기술 수업

v0.1 (2026-11-16) 사용자: "각 기술별 튜토리얼을 하나씩 만들어 보자. 만들 수 있는 기술들만. 사람들이 튜토리얼을 함으로써 해당 기술에 대해 확실하게 체감을 할 수 있도록 하자."

## 원칙: 먼저 안 되는 걸 겪고, 기술로 되게 한다

수업마다 첫 단계는 **기술 없이 해 보기**다. 실제로 안 되는 것을 겪은 뒤(놓았는데 안 잡힘, 손이 밀려남), 같은 자리로 돌아가 기술을 써서 된다. 마지막 단계에서 기술 이름을 알려 주고 정상을 잡으면 끝난다. 피로는 끈다.

## 수업 6개

| 수업 | 먼저 해 보기(안 됨) | 기술로 하기(됨) | 끝 |
|---|---|---|---|
| 하이스텝 `C_HIGH_T` | 오른손을 맨 위 홀드로 → 안 닿음 | 오른발을 허리 높이 발판에 → 잠깐 기다리면 몸이 올라감 → 오른손이 닿음 | 정상 |
| 매치 `C_MATCH_T` | 왼손을 오른손이 잡은 **초록** 홀드에 → 오른손이 밀려남 | 오른손이 잡은 **파란** 홀드에 왼손을 모음 → 두 손이 함께 잡힘 → 오른손이 다음 홀드로 | 정상 |
| 풋스왑 `C_FSWAP_T` | 오른발을 오른쪽 먼 발판으로 → 안 닿음 | 왼발을 오른발 자리에 → 오른발이 비켜남 → 오른발이 먼 발판에 닿음 | 정상 |
| 합발 `C_FMATCH_T` | (같음) | 왼발을 오른발이 딛은 파란 홀드에 같이 → 오른발이 먼 발판에 | 정상 |
| 크로스 `C_CROSS_T` | – | 오른손을 왼손 너머 왼쪽 홀드로("크로스" 인식) → 왼손이 더 왼쪽으로 | 정상 |
| 다이노 `C_DYNO_T` | 오른손을 맨 위(정상)로 → 안 닿음 | 가운데 두 번 + 아래로 끌고 떼기 → 날아가며 손 패드로 잡기 | 다른 손도 잡아 완등 |

- 홈 → 기술 → 처음 배우기 아래 "기술 수업" 줄(6장), 기술 사전 카드의 [연습하기](해 봤으면 ✓). 완료 화면 [다음]은 위 차례로 이어진다(`PlayFlow.TECH_SEQUENCE`).
- 다이노를 기술 사전에 넣었다(`T_DYNO`, 몸). "없는 기술"의 "데드포인트 · 다이노"는 "데드포인트"만 남겼다.

## 만들지 않은 것과 이유

| 기술 | 이유 |
|---|---|
| 플래그(+문 열림) | 한 손·한 발로 매달려도 몸이 저절로 그 아래로 정렬돼 문 열림이 거의 생기지 않는다. "균형 발"이 켜지는 자리도 찾지 못했다(벽 3가지 배치에서 0곳). 효과가 화면에서 느껴지지 않아 체감 수업이 안 된다 |
| 록오프 | 따로 하는 조작이 없다(한 손으로 잡고 다른 손을 뻗으면 게임이 굽힘) |
| 사이드풀·개스턴·언더클링 | 잡는 방향이 홀드 모양에 보이지 않는다(docs/42 §3.2) |
| 백스텝·드롭니 | 지금 몸에서 이득을 다시 재지 않았다(docs/42 §3.2) |
| 몸통 옮기기·휴식 | 이미 처음 배우기 2·3번 수업 |

## 만든 방법

- 벽: `tools/lessons/gen_tech_lessons.py` + `tech_params.json`(위치 값). 기본 수업 생성기도 `tools/lessons/gen_basic_lessons.py`로 옮겼다(전에는 임시 폴더에만 있었다).
- "먼저 해 보기" 판정: 놓았는데 못 잡으면 세션이 `miss` 이벤트를 남긴다(`{type: miss, limb, reason}`). 매치는 `slot_swap`, 풋스왑은 `pad_foot_swap`, 다이노는 `dyno_catch`.
- 검사 봇(SessionBot) 확장: 다이노 단계 `[손, "dyno", [끄는 x, y]]`, 몸통 끌기 `["BODY", "body", [dx, dy]]`, 다른 발이 딛은 발판에 발을 놓는 풋스왑. 두 손이 같은 홀드를 겨누지 않게 다이노 팔 배정을 고쳤다(정상 두 칸이 엇갈렸음).
- 시험(`tests/test_tech_lessons.gd`): 수업마다 실제 튜토리얼을 돌려 "먼저 해 보기"가 정말 안 되는지(목표 홀드에 안 붙음), 기술을 쓰면 끝까지 가는지 확인한다.
- 위치 고르기: 매치는 처음에 "모으기 전엔 오른손이 먼 홀드에 안 닿는다"로 짰는데, 몸이 따라가 모으지 않아도 닿았다(18곳 모두). 그래서 초록·파란 홀드 차이로 바꿨다. 풋스왑·합발은 먼 발판 위치를 15곳 재서 "기술 없이는 안 닿고 기술로는 닿는" 자리(오른쪽 0.95m)를 골랐다.
- 하이스텝은 발을 올린 뒤 몸이 1.5초쯤 걸려 올라간다. 몸통을 위로 끌면 오히려 멈춰서(다른 다리가 이미 다 펴짐) 문구를 "잠깐 기다리면 몸이 올라가요"로 했다.

## 확인 못 한 것

- 사람이 실제로 했을 때의 느낌. 특히 다이노 두 번 누르기(0.1초)와 매치의 "밀려남"이 알아보기 쉬운지.

## v0.3 (2026-11-18, 0.9.47) 벽 장식이 홀드를 가림

사용자(풋스왑 화면): "오른쪽에 발판이 안 보여. 홀드가 아닌 것들은 벽 밖에 위치시키거나 홀드와는 절대 겹치지 않도록 해야 해."

- 원인: 벽 판은 반폭 1.55m로 고정이었고, 벽 위 장식 볼륨(삼각 돌출 5개)을 가장자리 x ±1.25~1.5에 홀드와 상관없이 놓았다. 풋스왑·합발의 먼 발판(x 1.33)이 장식 밑에 들어갔다.
- 고침(`play_3d.gd`):
  - 벽 판 반폭 = max(1.55, 가장 바깥 홀드 |x| + 0.45). 홀드가 벽 판 가장자리·밖에 놓이지 않는다. 옆 벽(비활성 볼륨)도 벽 판 바깥으로 함께 민다.
  - 벽 위 장식은 벽 가장자리 0.35m 띠 안에서 고르되, 모든 홀드와 중심 거리 ≥ 장식 크기 × 0.8 + 0.35m인 자리만 쓴다(20번 시도해 없으면 그 장식은 뺀다).
  - 시험(`tests/test_wall_decor.gd`): 모든 문제·수업에서 장식 30가지 배치가 홀드와 겹치지 않고, 모든 홀드가 벽 판 안에 있다.
- "먼저 해 보기" 단계(하이스텝·풋스왑·합발)에서 목표 홀드를 노랗게 표시한다(`mark_slot`). 다이노 첫 단계 문구는 "맨 위 정상 홀드"로.
