# 51. 플레이어 입장 검토 — 아쉬운 점과 더 재밌어질 요소

v0.1 (2026-11-19). 사용자: "사용자 입장에서 게임을 하면서 어떤 부분이 아쉽고 가장 별로인지. 그리고 이런 요소가 있어야 더 재밌게 할 것 같다. 클라이머가 아니거나 클라이머인 사람들 둘 다의 입장에서 한번 봐줘."

**근거와 한계**: 0.9.51 기준 코드(`game/scenes/home.gd`·`play_test.gd`·`play_overlay.gd`, `game/data`), docs/01·41~50, 스크린샷(docs/images)을 읽고 쓴 검토다. 기기에서 직접 플레이하지 않았고, 다른 사람 테스트도 아니다. 아래 판단은 "이렇게 느낄 가능성이 크다"는 제안이며 측정 결과가 아니다.

## 0. 지금 게임에 있는 것

- 일반 문제 6개: 징검다리 V0, 비스듬히 V1, 모아서 뻗기·가는 사선·높은 디딤 V3, 실금 V8(체감 V4).
- 기술 수업 10개(기본 조작·발·몸통·팔 힘, 하이스텝·매치·풋스왑·합발·크로스·다이노).
- 결과 화면: "완등!" + 시간·추락 수 + 메달 3개(완등·무추락·시간)를 글자로.
- 떨어지면: 원인 글자와 함께 즉시 처음 자세로 돌아감.
- 소리: 위험(주의·위험·심장 소리)과 회복 4개뿐. 배경음, 잡는 소리, 완등 소리는 없다.
- 도움: 위험 게이지를 누르면 자동 도움(팔다리 한 번씩), 무게중심·하중 뼈대 표시(설정에서 켜기).
- 꾸미기: 남·여·더미, 여성 옷 교체.

## 1. 가장 별로인 것 (우선순위 순)

### 1.1 성취의 순간이 밋밋하다 — 가장 크다

이 게임의 재미 중심은 "어려운 자세를 풀어낸 성취감"(docs/01)인데, 그 순간을 받쳐 주는 연출이 거의 없다.

- **완등**: 탑을 잡으면 어두운 판에 글자가 뜬다. 실제 볼더링에서 가장 기분 좋은 순간(탑 매치 → 뒤돌아 뛰어내리기 → 매트 착지)이 화면에 없다. 소리·진동도 없다.
- **추락**: 떨어지는 장면 없이 순간이동으로 처음 자세가 된다. 왜 떨어졌는지는 글자로 나오지만, 몸이 미끄러지는 느낌이 없어 "실패 원인"이 손끝으로 느껴지지 않는다.
- **잡기**: 홀드를 잡을 때 소리·진동·작은 먼지(초크) 같은 손맛이 없다. 네 손가락 조작은 손맛이 전부인 장르라 이 차이가 크다.

비클라이머는 "깼는데 별 느낌이 없다", 클라이머는 "센드(완등)한 맛이 안 난다"로 느낄 가능성이 크다.

### 1.2 할 거리가 적고 등급 사다리에 빈칸이 많다

- 일반 문제 6개를 다 깨는 데 몇십 분이면 된다(문제당 40초~3분 목표, docs/01).
- V2, V4~V7이 비어 있다. V3 세 개 다음이 바로 V8인데 체감은 V4라 표기와 실제가 어긋난다.
- 다 깬 뒤에 다시 할 이유가 메달 두 개(무추락·시간)뿐이다.

### 1.3 처음 10분의 벽이 높다 (비클라이머)

- 휴대폰을 내려놓고 네 손가락을 쓰는 조작 자체가 처음엔 낯설다. 지하철·누워서 하기 어렵다.
- 기본 수업 4개 + 기술 수업 6개를 거쳐야 "등반을 한다"는 느낌이 온다. 수업이 많고, 수업과 문제가 따로 논다.
- V0·V3·V8 같은 등급 표기는 비클라이머에게 의미가 없다.

> 참고: AGENTS.md 규칙상 네 팔다리 독립 조작을 두 엄지 조작으로 바꾸지 않는다. 그래서 "조작을 쉽게"가 아니라 "처음에 덜 막막하게"로 풀어야 한다(§3).

### 1.4 화면이 문제를 "읽게" 해 주지 않는다

- 벽이 한 가지 주황색 + 점무늬이고, 벽 밖 큰 삼각형·상자 장식이 홀드보다 눈에 띌 때가 있다(스크린샷 route_g_v3_03).
- 홀드 색이 "용도"(손·발·목표·매치)를 뜻한다. 클라이머에게 색은 보통 "이 문제"를 뜻하므로 처음에 헷갈린다.
- 시작 전에 벽 전체를 훑어보는 시간(루트 읽기)이 없다. 실제 볼더링에서는 오르기 전 아래에서 순서를 읽는 것이 재미의 절반이다.
- 개발용 글자(화면 크기·dpi·데드존)가 화면 아래에 보인다(스크린샷 기준, 출시 빌드에서는 숨겨야 함).

### 1.5 클라이머가 보면 아쉬운 사실감

- 벽이 수직뿐이다. 오버행(벽 기울기)이 없으면 V5 이상의 "몸 긴장" 감각이 안 나온다 → docs/48 R2로 계획됨.
- 힐훅·토훅, 몸이 벽에서 흔들려 떨어지는 바른도어(문 열림)의 손맛 → R3·R5로 계획됨.
- "플래시"(첫 시도 완등)와 "레드포인트"(여러 번 끝에 완등)의 구분이 없다. 무추락 메달이 비슷하지만 이름이 클라이머 말과 다르다.
- 등급 체감이 표기와 어긋난다(실금 V8 → 체감 V4). 클라이머는 바로 알아챈다.

## 2. 사람별로 무엇을 원할까

| | 비클라이머 | 클라이머 |
|---|---|---|
| 처음 기대 | "벽 타는 게임" 손맛·쾌감 | "진짜 볼더링 같은가" |
| 가장 막히는 곳 | 조작 익히기, 왜 발을 써야 하는지 | 등급이 맞는지, 기술이 진짜처럼 작동하는지 |
| 좋아할 것 | 연출·소리, 짧은 성공, 꾸미기, 보상 | 루트 읽기, 정확한 기술, 어려운 문제, 직접 만든 문제·기록 비교 |
| 떠나는 이유 | 처음 10분에 막힘, 깨도 재미 없음 | 문제 수 적음, 등급이 엉터리, 오버행 없음 |
| 이미 잘 된 점 | 무게중심·하중 표시, 자동 도움, 짧은 문제 | 발 몫·손 피로, 하이스텝·매치·풋스왑·다이노 |

## 3. 있으면 더 재밌을 것 (제안, 우선순위 순)

### A. 바로 해 볼 만한 것 (작업 작고 효과 큼)

1. **완등 연출**: 탑 매치 → 짧은 멈춤 → 뛰어내려 매트 착지(또는 주먹 쥐기) + 완등 소리 + 진동. 메달은 하나씩 찍히게.
2. **추락 연출**: 0.5~1초 미끄러져 매트에 떨어지는 장면 → 원인 글자 → 바로 다시. 원인별로 손이 빠지는지·발이 미끄러지는지 다르게 보이면 실패가 배움이 된다.
3. **잡기 손맛**: 홀드 잡을 때 짧은 소리·진동, 손 놓을 때 초크 가루. 좋은 홀드와 나쁜 홀드의 소리를 다르게.
4. **루트 읽기 시간**: 시작 전 카메라가 탑에서 시작 홀드로 내려오며 문제를 보여 줌(건너뛰기 가능).
5. **개발용 글자 숨기기**(출시 빌드).

### B. 다시 하게 만드는 것

6. **빈 등급 채우기**: V2, V4~V7을 등급마다 2~3개. 표기 등급을 체감 등급에 맞춰 다시 붙이기(실금 → V4 등).
7. **플래시 메달**: 첫 시도에 완등하면 따로 표시. 클라이머 말과 맞고, 비클라이머에게도 "한 번에!"는 쉽게 와닿는다.
8. **내 고스트**: 내 최고 기록이 반투명하게 같이 오름. 시간 메달의 재미를 키운다.
9. **막히면 시범 보기**: 이미 있는 검사 봇(`route_bot.gd`)의 정답 순서를 짧게 보여 주는 "베타 보기". 쓰면 메달 일부는 못 받게.
10. **비클라이머용 등급 이름**: "V3" 옆에 쉬움·보통·어려움 같은 말이나 별 개수를 함께.

### C. 오래 하게 만드는 것 (작업 큼)

11. **수업과 문제 잇기**: 수업을 끝내면 그 기술이 꼭 필요한 문제 하나가 바로 열리고, 문제에서 막히면 해당 수업으로 안내.
12. **벽 기울기·훅**(docs/48 R2~R5): 클라이머를 붙잡는 핵심. 이미 계획대로.
13. **문제 만들기와 공유**: 클라이머에게 가장 오래 가는 재미는 직접 문제를 짜고 친구에게 내는 것(트레이닝 보드 앱들이 오래 쓰이는 이유). 이미 있는 검사 도구(격자 검사·탐색기·봇)로 "깰 수 있는 문제인지" 자동 확인할 수 있다는 것이 큰 장점이다.
14. **오늘의 문제**: 매일 하나, 같은 문제로 기록 비교.
15. **벽 테마**: 지금 주황 실내 벽 하나 → 다른 체육관·야외 바위. 아트 비용이 커서 나중.

## 4. 내 판단 — 다음에 하면 좋을 순서

1. **A(연출·손맛)를 먼저** 한 번에 묶어서 한다. 문제를 아무리 잘 만들어도 깨는 순간이 밋밋하면 재미가 전달되지 않는다. 판정 로직은 건드리지 않고 표현(화면·소리)만 바꾸므로 지금 진행 중인 docs/48 작업과 부딪히지 않는다.
2. 그다음 docs/48 순서(R7 관문 검사 → R2 벽 기울기 …)로 돌아가면서, **B-6 빈 등급 채우기**를 같이 한다. R7 검사 도구가 있으면 문제 제작이 빨라진다.
3. **B-7·8·9**(플래시·고스트·시범 보기)는 각각 작아서 사이사이 넣는다.
4. **C-13 문제 만들기**는 콘텐츠가 20개쯤 쌓이고 판정이 안정된 뒤에 기획한다.

## 5. 확인이 필요한 것

- 위 1장은 직접 플레이가 아닌 코드·스크린샷 판단이다. 특히 "처음 10분의 벽"(1.3)은 클라이밍을 안 해 본 사람 2~3명에게 설명 없이 시켜 보는 것이 가장 확실하다(docs/01의 T01 3분 기준).
- 홀드 색을 "문제 색"으로 바꿀지(1.4)는 지금 색이 튜토리얼 안내 역할도 하므로 사용자 결정이 필요하다.
