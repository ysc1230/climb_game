# 작업 1 연출·손맛 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 판정을 바꾸지 않고 완등·추락·손 힘 바닥·잡기 순간을 화면·소리·진동으로 느끼게 하고, 손 그림과 잡힘 위치를 맞추고, 오르기 전 루트 읽기를 넣는다.

**Architecture:** 새 계산(경고 단계, 잡기 손맛 고르기, 루트 읽기 시간, 낙하 인형, 조언 문구)은 노드 없는 `RefCounted` 클래스로 만들고 `game/tests/test_*.gd`로 검증한다. 화면 쪽(`play_test.gd` 2D 논리·UI, `play_3d.gd` 3D 그리기, `climber_pose.gd`)은 그 결과를 읽어 그리기만 한다. 세션에는 기본값 `false`인 멈춤 플래그 둘만 더해 봇·기존 테스트 결과를 그대로 둔다.

**Tech Stack:** Godot 4.7.2 GDScript, 헤드리스 테스트 `godot --headless --path game --script res://tests/run_tests.gd`(파일 하나만: `-- test_x.gd`), Python 3 표준 라이브러리(효과음 합성).

**Spec:** `docs/superpowers/specs/2026-11-19-1-feel-design.md`

## Global Constraints

- 판정 수치(피로·지지·잡기 반경·`Tuning`) 변경 금지. 봇(`SessionBot`·`RouteBot`)과 기존 테스트 결과가 바뀌면 안 된다.
- 판정 로직은 노드 없는 순수 GDScript, 표현은 스냅숏을 읽기만(AGENTS.md).
- 화면은 휴대폰 가로 기준.
- 모든 연출은 화면을 누르면 건너뛴다.
- 손 힘 경고: 주의 < 40 들어감 / ≥ 45 나감, 위험 < 20 들어감 / ≥ 25 나감. 고급(`Progress.level == "advanced"`)은 게이지 깜빡임만.
- 색: 크림 `#F1D59A`, 청록 띠 `#8FD0BC`, 파랑 띠 `#9CC0F4`, 주황 `#ff9a7a`, 흰색. 흰색 빛은 "지금 놓으면 잡힘" 전용.
- 새 소리 파일은 `game/art/sfx/`에 두고 출처·조건을 `docs/14_asset_manifest.md`에 적는다.
- 헤드리스·화면 캡처를 기기 확인으로 보고하지 않는다.
- 커밋 메시지 끝에 저장소 규칙의 Co-Authored-By/Claude-Session 줄.

## Review Focus

1. 완등 순간 네 손가락이 아직 패드를 누르고 있음 → 멈춘 세션에 입력이 들어가지 않고, [다시] 뒤 패드가 정상 동작. (Task 1 테스트 `test_hold_on_clear_ignores_input`)
2. 낙하 시뮬레이션이 벽 속으로 들어가거나 숫자가 NaN이 됨(속도 0·손 하나만 붙은 상태·매트 바로 위에서 떨어짐) → 항상 매트 위에서 1.6초 안에 멈춤. (Task 7 테스트 `test_fallsim_edge_starts`)
3. 손 힘이 39↔41을 오가며 경고가 깜빡깜빡 켜졌다 꺼짐 → 5점 여유로 한 번만 바뀜. (Task 3 테스트 `test_warning_hysteresis`)
4. 네 손발을 한 틱에 동시에 잡음 → 소리 하나, 진동 하나. (Task 4 테스트 `test_feel_dedupe_same_window`)
5. 루트 읽기 중이나 낙하 장면 중 일시정지·앱 전환 → 돌아오면 그 장면이 이어지거나 끝으로 가고 입력이 막힌 채 남지 않음. (Task 6·7 각 `test_*_skip_and_resume`)
