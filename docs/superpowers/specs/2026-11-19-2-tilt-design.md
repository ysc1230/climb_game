# 작업 2. 몸 옮기기: 휴대폰 기울이기 설정

2026-11-19 · 전체 순서는 [작업 1 문서 끝](2026-11-19-1-feel-design.md#작업-전체-순서). 표시: **[사용자]** / **[제안]**.

## 왜 하는가

**[사용자]** 지금은 네 패드 사이 가운데를 끌어서 몸(무게중심)을 옮긴다. 사용자들이 휴대폰 기울기로 옮기게 해 달라고 요청했다. 설정에서 둘 중 하나로 바꿀 수 있게 한다.

## 목표 · 비목표 · 반목표

- 목표: 휴대폰을 손에 들고 할 때 가운데를 누르지 않고 몸을 옮길 수 있다.
- 비목표: 손발 조작 변경(네 패드 그대로, AGENTS.md), 판정 변경. 기울이기는 가운데 끌기와 **같은 판정 입구**(`rules.body_goal`)만 쓴다.
- 반목표: 가만히 들고 있는데 몸이 저절로 흘러가는 것. 손 떨림에 몸이 떨리는 것.

## 화면 (설정 탭, 휴대폰 가로)

시안: [캔버스 4번](https://claude.ai/artifact/Mr143fvFoggn2B7ETRzNWZ)(16:9로 그렸음, 실제는 20:9 가로).

| 항목 | 값 | 기본 |
|---|---|---|
| 몸 옮기기 | [가운데 끌기] [휴대폰 기울이기] | 가운데 끌기 |
| 민감도 (기울이기일 때만) | 1~5 | 3 |
| 반응 시작 각도 | 0~10° | 3° |
| [지금 기울기를 기준으로 맞추기] | 버튼 | — |
| 기울이기 중에도 가운데 끌기 함께 쓰기 | 켜기/끄기 | 켜기 **[제안]** |

- 기울기 센서가 없으면(중력 벡터가 0) [휴대폰 기울이기]를 흐리게 하고 "이 기기는 기울기 센서가 없어요"를 보인다.
- 설정은 지금 설정 저장 방식(`progress`/`save_store`)에 같이 저장한다. 저장 형식이 바뀌면 docs/09를 같이 고친다.

## 동작 [제안]

- 기준: 문제를 시작할 때(루트 읽기가 끝나는 순간) 그때 기울기를 0으로 잡는다. 기준 맞추기 버튼을 누르면 그 순간으로 다시 잡는다.
- 축: 좌우로 기울이면 몸이 좌우로, 화면 위쪽을 앞으로 숙이면 몸이 위로, 뒤로 젖히면 아래로.
  - 가로 화면은 방향이 둘(정방향 가로·뒤집힌 가로)이다. Godot 안드로이드가 센서 값을 화면 회전에 맞춰 이미 돌려 주는지 **기기에서 먼저 확인**한다(확인 전에는 모름). 돌려 주면 그대로 쓰고, 안 돌려 주면 `DisplayServer.screen_get_orientation()`으로 축을 바꾼다. 확인 결과를 이 문서에 적는다.
- 각도 → 몸 목표: **위치 방식**(기울인 만큼 그 자리, 속도 방식 아님).
  - 각 축의 각도 a에서 반응 시작 각도 d를 빼고(|a| ≤ d면 0), 민감도별 최대 각도 R로 나눠 −1~1로 자른 뒤 `Tuning.BODY_GOAL_MAX`(0.45m)를 곱한다.
  - R: 민감도 1 → 25°, 2 → 20°, 3 → 15°, 4 → 11°, 5 → 8°.
  - 손 떨림을 거르기 위해 각도에 저역 통과 필터(프레임당 0.15 섞기)를 건다.
- 판정으로 넘기기: 새 입력 명령 `body_tilt {offset}`을 `ClimbSession._body_input`에 더한다. 기울기가 반응 범위를 처음 벗어나는 순간의 골반을 기준점으로 잡고 `rules.body_goal = 기준점 + offset`. 두 축 모두 반응 범위 안으로 돌아오면 목표를 **지운다**(`rules.body_goal`을 목표 없음 값으로 — 몸은 자동 자세로 자리를 잡음) **[제안]**. 참고: 지금 가운데 끌기의 `body_end`는 목표를 지우지 않고 남긴다(손을 떼도 그 자리에 머묾). 기울이기는 "기울인 동안만 옮김"이라 다르게 한다. 목표 없음 값(NaN 등)은 지금 `ClimbRules`를 따른다.
- 가운데 끌기와 함께 쓸 때: 가운데를 끄는 동안은 가운데 끌기가 이긴다. 손을 떼면 기울이기가 다시 받는다(그 순간 골반을 새 기준점으로).
- 손발 패드를 누르고 있는 동안에도 기울이기는 계속 먹는다(지금 "가운데를 누른 채 손을 뻗는" 방식과 같음).
- 기술 선택 중(게임 시간 정지)·루트 읽기·완등·낙하 중에는 무시한다.
- 지금 가운데 끌기는 "다른 팔다리를 움직이기 시작하면 목표를 지운다"(`_body_input` 주석). 기울이기에서는 이 규칙을 적용하지 않는다(기울인 동안은 계속 목표). 만드는 사람이 판정 쪽 영향이 없는지 테스트로 확인.

## 코드 자리

- 각도 → offset 계산: 노드 없는 `TiltMapper`(새 파일 `game/scripts/input/tilt_mapper.gd`). 입력: 중력 벡터, 화면 방향, 기준, 설정. 출력: offset(Vector2), active(bool). 헤드리스 테스트.
- 센서 읽기: `play_test.gd::_process`에서 `Input.get_gravity()`를 읽어 `TiltMapper`에 넣고, 결과를 다른 입력 명령과 같이 `session.apply_input`으로 보낸다.
- 검사 봇은 기울이기를 쓰지 않는다.

## 검증

- 헤드리스: 반응 범위 안 0, 축 방향(두 가로 방향 모두), 민감도별 최대, 필터, 가운데 끌기 우선, 범위 복귀 시 목표 끝.
- 기기: 들고 하기·책상에 놓고 하기 둘 다 사용자 확인(APK).

## 만드는 사람에게 맡기는 것

필터 상수 미세 조정, 설정 화면 세부 배치(시안 기준), 기준 맞추기를 문제마다 자동으로 할지 첫 문제만 할지(기본: 문제마다).


## 구현 기록 (2026-11-20, 0.9.54)

- `TiltMapper`(`game/scripts/input/tilt_mapper.gd`): 화면 기준 중력 → (좌우°, 앞뒤°) → 기준과의 차 → 반응 시작 각도 빼고 민감도 최대 각도로 나눠 ±1 → × 0.45m. 필터는 판정 틱(60/s)마다 0.15 섞기.
- 판정: `ClimbSession` 입력 `body_tilt`(docs/09 "몸 옮기기 설정"). 기울인 동안은 다른 팔다리를 움직여도 목표 유지. 다이노 준비·날기 중에는 기존대로 몸 입력을 받지 않는다.
- 플레이 화면: 판정 틱마다 `Input.get_gravity()`. 루트 읽기·완등·낙하·기술 선택·일시정지 중에는 보내지 않는다. **튜토리얼에서는 끈다**(가운데 끌기를 가르치는 단계라서, 만든 사람 판단). 기울이기만 쓸 때는 가운데 끌기 명령만 버리고 가운데 두 번 누르기(다이노)는 그대로.
- 기준 맞추기: **설정의 [지금 기울기를 기준으로 맞추기] 버튼은 만들지 않았다**(만든 사람 판단). 시도마다(문제 시작·[다시]·떨어진 뒤 다시) 루트 읽기가 끝난 뒤 첫 값을 0으로 잡으므로, 설정 화면에서 잡은 기준은 쓸 곳이 없다. 플레이 중 다시 맞추고 싶다는 요청이 있으면 일시정지 메뉴에 둔다.
- 센서: 프로젝트 설정 `input_devices/sensors/enable_gravity=true`(Godot 4.7 기본 꺼짐 — 끄면 기기에서도 0). 센서 값이 0이면 [휴대폰 기울이기]를 흐리게 하고 "이 기기는 기울기 센서가 없어요". 값이 늦게 들어오면 설정 탭을 다시 그린다.
- 축: 센서 값이 화면 회전을 따른다고 가정(`screen_aligned=true`), 중력은 땅 쪽을 가리킨다고 가정. **기기 확인 전** — 방향이 반대로 움직이면 이 가정이 틀린 것이다(부호 하나 고치면 됨). 따르지 않는 기기를 위한 두 가로 방향 변환(`TiltMapper.to_screen`)은 있으나 쓰지 않는다.
- 검증: `test_tilt_mapper` 7, `test_body_drag` 기울이기 3, `test_progress::test_control_settings`, `test_play_screen` 기울이기 3. 데스크톱 캡처 [설정 탭](../../images/tilt_settings.png)(데스크톱은 센서가 없어 안내 문구가 보임). 기기 미검증: 들고 하기·책상에 놓고 하기.
