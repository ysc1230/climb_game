# 작업 4. 홀드 종류·방향·크기와 홀드·벽 새 그림

2026-11-19 · 전체 순서는 [작업 1 문서 끝](2026-11-19-1-feel-design.md#작업-전체-순서). 표시: **[사용자]** / **[제안]**.

## 왜 하는가

**[사용자]**

- 지금 홀드는 발홀드·손홀드·합손(발)홀드 세 개가 끝이고 크기만 다르다. 저그·크림프 같은 다양한 홀드가 있고, 종류에 따라 필요한 힘이 달랐으면 좋겠다.
- 홀드 방향이 있고, 방향에 따라 무게중심과 받는 힘이 달라졌으면 좋겠다. 방향은 고정하지 말고 **5°씩 자유롭게** 바꿀 수 있게.
- 홀드 **크기에 따라서도 능력치가 달라진다**.
- 홀드가 너무 못생겼다. 어떤 홀드인지 모르겠고 다 슬로퍼나 크림프처럼 보인다. 벽과 배경도 바꾸고 싶다(캐릭터는 나중에 천천히).
- 색은 **지금처럼 용도로 구분**한다.
- 참고 그림: 사용자가 준 실내 볼더링 벽 일러스트(아래 "그림 방향"). 원본은 이 문서와 같은 커밋의 `docs/images/ref_wall_holds.png`.

이 작업은 **판정을 바꾼다**(홀드 데이터와 지지·피로 계산에 종류·방향·크기가 들어감). 그래서 문제 제작(작업 5)과 문제 만들기(작업 6) 앞에 한다.

## 목표 · 비목표 · 반목표

- 목표: 모양만 봐도 홀드 종류를 알고, 종류·크기·방향이 몸으로 느껴지게 다르다.
- 비목표: 벽 기울기(뒤로 미룸), 캐릭터 새 그림(뒤로 미룸), 볼륨(큰 덩어리)을 잡는 홀드로 쓰기(이번에는 장식만 **[제안]**).
- 반목표: 색을 섞어 용도를 알 수 없게 되는 것(사용자가 지금 색 유지로 정함). 방향 효과를 "옆 방향이면 무조건 ○○" 같은 손 규칙으로 흉내 내는 것 — 방향은 **지지 계산의 힘 방향을 돌리는 것으로** 생겨야 한다.

## 4.1 홀드 데이터 [제안]

지금 슬롯은 `hand_area {dir, half_width, matchable}`, `foot_area {up, half_height, half_width}`, `grip_modes [{mode, axis, half_angle}]`를 가진다(`route_def.gd`). `grip_modes`의 pull 말고 다른 방식(sidepull·undercling·gaston)은 시험 루트 `TX_TECH`에서만 쓰이고, 실제 문제·수업 16개는 모두 기본값(pull, 위, 65°)이다. 새 필드 셋을 더하고, 이 셋에서 기존 필드를 **만들어 낸다**.

| 새 필드 | 값 | 뜻 |
|---|---|---|
| `hold_type` | `jug` `crimp` `sloper` `pinch` `pocket` `foot_chip` `foot_big` `goal` | 종류 |
| `size` | `S` `M` `L` | 크기 |
| `rot_deg` | 0~355, 5의 배수 | 방향. 0 = 손이 걸리는 날(밝은 띠)이 위를 향함 = 손은 아래로 당김. 시계 방향으로 늘어남(90 = 날이 오른쪽을 향함) |

- 읽기 규칙: 새 필드가 있으면 아래 표로 `hand_area`·`foot_area`·`grip_modes`를 만든다. 없으면 지금처럼 읽는다(기존 문제 그대로 동작). 둘 다 있으면 새 필드가 이긴다.
- 종류의 수치는 `game/data/hold_types.json`(새 파일)에 둔다. 코드 상수가 아니라 데이터라 조정이 쉽다. docs/04에 표를 옮겨 적는다(AGENTS.md: 조정값은 04와 일치).

### 종류 표 (출발값, 기기에서 조정)

| 종류 | 손/발 | 반폭 S/M/L(m) | 힘 방향(rot 0 기준) | 반각 | 피로 배율 | 그 밖 |
|---|---|---|---|---|---|---|
| jug 저그 | 손 | 0.07 / 0.09 / 0.12 | pull 위로 | 80° | ×0.7 | 쉬는 자리. 합손은 `matchable`로 따로 |
| crimp 크림프 | 손 | 0.035 / 0.045 / 0.06 | pull | 50° | ×1.3 | — |
| sloper 슬로퍼 | 손 | 0.08 / 0.10 / 0.13 | pull | 45° | ×1.15 | **몸 창**: 무게중심이 홀드 아래 좌우 ±0.12m 안이면 품질 1, 0.35m 밖이면 0.4(선형). 품질은 기존처럼 피로·최대 하중에 들어감 |
| pinch 핀치 | 손 | 0.04 / 0.05 / 0.065 | pull + 옆 둘(rot ±90°) | 각 55° | ×1.1 | 좌우로 당겨도 버팀 |
| pocket 포켓 | 손 | 0.03 / 0.04 / 0.05 | pull | 60° | ×1.5 | 합손 불가(`matchable` 무시) |
| foot_chip 작은 발판 | 발 | 반높이 0.03 / 0.04 / 0.05 | — | — | — | 발 몫 ×0.85 |
| foot_big 큰 발판 | 발 | 0.05 / 0.06 / 0.08 | — | — | — | 발 몫 ×1.0 |

- 풋스왑·합발 규칙은 **바꾸지 않는다** **[제안]**: 두 발판 종류 모두 지금처럼 풋스왑이 되고, 합발은 지금처럼 합손 가능(`matchable`) 홀드에서만 된다. 그래서 풋스왑 수업(`C_FSWAP_T`)이 그대로 동작한다.
| goal 탑 | 손 | 0.12 고정 | pull | 80° | ×0.7 | 지금 탑과 같음 |

- **크기 효과**: 반폭이 크기마다 달라서 지금 있는 작은 홀드 피로 배율(`Fatigue.size_multiplier`, 반폭 0.08 미만일수록 빨리 지침)이 그대로 걸린다. 더해서 반각을 S −5°, L +5°.
- **방향 효과**: `rot_deg`만큼 `hand_area.dir`(손 닿는 선분)과 모든 `grip_modes.axis`(홀드가 손에 주는 힘의 방향)를 돌린다. 그러면 지지 계산(`SupportSolver`)이 자연스럽게:
  - 날이 옆을 향하면(사이드풀) 몸이 반대쪽에 있어야 힘이 맞고,
  - 날이 아래를 향하면(언더클링) 발이 높고 몸이 홀드보다 낮아야 버틴다.
  - mode 이름은 rot로 고른다: 0±40 pull, 90±40 sidepull(또는 반대쪽), 180±40 undercling, 그 사이는 가까운 쪽. 이름은 기술 판정·안내 문구에 쓰이므로 유지한다.
- **발판의 방향**: `foot_area.up`을 `rot_deg`만큼 돌린다(비스듬한 발판).
- **슬로퍼 몸 창**: 새 판정 규칙이라 `GripCheck`/`HoldArea`의 접점 품질 계산에 더한다(노드 없음, 테스트).
- 판정 수치 판 `TUNING_VERSION`을 올리고 docs/50 능력치 표에 새 줄을 더한다.

### 기존 문제 옮기기

- 기존 문제 JSON에 새 필드를 채운다. 손홀드: 합손이거나 반폭 ≥ 0.08 → jug, 반폭 < 0.05 → crimp, 그 사이 → jug S. 발: foot_chip M. 탑: goal. 크기는 가장 가까운 반폭으로. rot는 지금 `grip_modes[0].axis`에서 계산(실제 문제·수업은 모두 기본값이라 rot 0).
- 옮긴 뒤 기존 문제의 봇 결과(완등·최저 손 피로)가 크게 바뀌면 표로 기록하고, 체감 등급을 다시 받아야 할 문제를 적는다. 판정 결과가 같도록 옮기는 게 목표가 아니다(종류가 생겼으니 달라져도 됨). 다만 지금 깨지는 문제가 못 깨지면 배치를 고친다.
- `content_version`을 올린다(저장된 기록이 새 판정 기준으로 다시 매겨지게, docs/09).

## 4.2 홀드 그림

### 그림 방향 — 참고 그림에서 가져올 것

| 요소 | 참고 그림 | 우리 홀드 |
|---|---|---|
| 모양 | 종류마다 확실히 다름: 깊게 파인 통(저그), 얇은 날(크림프), 둥근 덩어리(슬로퍼), 바나나·갈비 모양(핀치), 구멍 뚫린 도넛(포켓), 작은 칩(발) | 같음. 정면(등 뒤) 카메라에서도 구분되게 실루엣을 크게 다르게 |
| 볼트 | 가운데 볼트 머리(육각 구멍) | 모든 홀드에 볼트 머리 |
| 외곽선 | 얇은 잉크 선 | 지금 외곽선 셰이더(`outline.gdshader`) |
| 질감 | 무광 레진, 점박이 얼룩, 모서리 닳음 | 툰 셰이더에 점박이 얼룩(노이즈) 추가 |
| 그림자 | 오른쪽 아래로 부드러운 그림자 | 지금 주광 방향(왼쪽 위) 유지 |
| 색 | 섞여 있음 | **섞지 않음 [사용자]** — 지금 색 그대로: 손 `#2B7A6F`/띠 `#8FD0BC`, 합손 `#2F5FC4`/`#9CC0F4`, 발 `#5E4C70`/`#C4B0D6`, 탑 `#D9B872`/`#F1D59A`. 흰색은 "지금 놓으면 잡힘" 빛 전용(docs/32) |

- 손이 걸리는 날에 밝은 띠를 칠하는 규칙(docs/32)은 유지한다. 슬로퍼는 날이 없으므로 윗면 넓게 밝은 면.
- 모델: 종류마다 2~3개 변형 × 크기는 메시 늘리기. `tools/holds/make_holds.py`(Blender 배경 실행)를 고치거나 새 생성기를 만든다. Blender MCP로 보며 다듬어도 된다. 출력 `game/art/holds/holds.glb`.
- 홀드 메시는 판정 영역과 크기가 맞아야 한다(docs/32 §3의 늘리기 규칙을 종류별로 다시 정함).
- `rot_deg`대로 메시를 돌린다.

## 4.3 벽 · 배경 · 매트

| 요소 | 지금 | 바꿀 것 |
|---|---|---|
| 벽 판 | 주황 판 몇 장, 점무늬 | 합판 판넬(약 1.2m 칸)과 이음선, 판마다 아주 조금 다른 톤, 가장자리 어둡게, 얼룩 질감 |
| 볼트 구멍 | 셰이더 점(`bolt_spacing` 0.2) | 규칙적인 격자 구멍(참고 그림처럼), 살짝 음각 느낌 |
| 장식 | 큰 삼각형·상자가 화면 앞에 떠 있음 | **볼륨**: 벽에 붙은 삼각기둥·상자(모래·황토색, 볼트). 문제 영역 밖(좌우 가장자리)에만, 홀드와 절대 겹치지 않게(기존 `deco_spots` 규칙 유지·강화) |
| 옆벽·천장 | 주황 판 | 옆벽은 같은 합판 톤으로 어둡게, 화면 밖으로 빠지게 |
| 바닥 매트 | 상자 하나(`play_3d.gd`, 두께 0.25m) | 같은 자리·크기에 회색 매트 그림, 이음선·천 질감(작업 1의 추락 착지와 공유) |

- 홀드가 벽보다 먼저 읽혀야 한다(docs/01 "아트와 가독성의 양립"). 벽 대비를 확인하려고 캡처를 흑백으로 바꿔 봤을 때도 홀드가 보여야 한다.

## 4.4 문제 화면에서 종류 보이기

- 문제 시작 전 루트 읽기(작업 1.6) 동안, 처음 보는 종류가 있으면 그 홀드 옆에 이름표("슬로퍼")를 잠깐 띄운다(종류마다 한 번, `seen_tips`).
- 기술 사전처럼 "홀드 사전"을 설정 또는 기술 탭에 둔다 **[제안]**: 시안의 홀드 카드(종류·손 힘 빠짐·버티는 방향·특징).

## 검증

- 헤드리스: 새 필드 읽기·옛 형식 읽기, 종류 표 → grip_modes 만들기, rot 돌리기(0·90·180·275), 사이드풀에서 무게중심이 반대쪽일 때만 지지 성립, 언더클링은 발이 높을 때 성립, 슬로퍼 몸 창 품질, 포켓 합손 불가, 크기별 반폭·반각.
- 기존 6문제·수업 10개 봇 다시 재기, 결과 표를 이 문서에 기록.
- 화면 캡처: 종류 8개 나란히(정면 카메라), 벽 전체, 흑백 가독성.
- 기기: 사용자 확인(APK).

## 만드는 사람에게 맡기는 것

종류별 메시 모양 세부, 질감 노이즈 방식, 판넬 크기·이음선 굵기, 볼륨 배치 수, 종류 표 수치의 첫 조정.
