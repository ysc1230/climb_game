# 작업 5. 빈 등급 문제 채우기 (R7 관문 검사 도구 포함)

2026-11-19 · 전체 순서는 [작업 1 문서 끝](2026-11-19-1-feel-design.md#작업-전체-순서). 표시: **[사용자]** / **[제안]**.

## 왜 하는가

일반 문제가 6개(V0, V1, V3×3, V8)라 금방 끝난다. V2와 V4~V7이 비어 있고, V8 "실금"은 사용자 체감이 V4였다(docs/44). **[사용자 승인한 제안]** 실금을 V4로 바꾸고 새 문제를 만든다. 목표 "등급마다 2개 이상"을 채우려고 V0·V1에도 하나씩 더해 **11개**로 한다 **[제안]**. 작업 4의 새 홀드 종류·방향으로 만든다.

## 목표 · 비목표 · 반목표

- 목표: V0~V7이 등급마다 2개 이상, 등급 표기와 체감이 맞음, 등급이 오를 때 필요한 기술이 하나씩 늘어남.
- 비목표: V8 이상(docs/48의 V12·V15는 R1~R7이 다 있어야 함, 벽 기울기 미룸), 기술 수업 새로 만들기.
- 반목표: 몸통 끌기로 관문이 뚫려 "기술이 필요하다"가 거짓이 되는 것(docs/47에서 겪음).

## 5.1 먼저: R7 관문 검사 도구

docs/48 §R7 그대로: 관문 자리에서 "그 기술 없이" 골반을 닿는 범위 전체(격자 0.05m)로 옮겨 가며 힘 해(지지 성립)가 하나라도 있는지 본다. 탐색기(`path_explorer.gd`)에 기술 금지(하이스텝·매치·풋스왑·합발·크로스·다이노와, 작업 4로 생긴 방향 홀드)를 더한다.

- 출력: 관문마다 "기술 없이 성립하는 자세 수"(0이어야 진짜 관문), 탐색기 기술 금지 결과(길 없음이어야 함).
- 먼저 기존 기술 수업 6개를 이 도구로 다시 검사해 결과를 docs/48 §11에 남긴다(docs/48 §9 단계 2).

## 5.2 만들 문제

| 등급 | 수 | 이 등급의 주제 [제안] | 관문(`score_gates`) | 쓰면 좋은 새 홀드 |
|---|---|---|---|---|
| V0 | 1 | 손발 하나씩. 홀드가 크고 가까움 | 없음 | 저그·큰 발판 |
| V1 | 1 | 발을 먼저 올리기 | 없음 | 저그·작은 발판 |
| V2 | 2 | 발을 먼저·몸통 옮기기. 기술 없이 깨지만 쉬는 자리를 찾아야 함 | 없음 | 저그·큰 발판 |
| V4 | 1 (+ 실금) | 기술 하나가 꼭 필요(매치 또는 하이스텝) | 1 | 크림프·작은 발판 |
| V5 | 2 | 쉬는 자리를 이어 가기. 작은 홀드 구간을 짧게 | 1 | 크림프·포켓·저그 쉬는 자리 |
| V6 | 2 | 기술 둘을 이어 쓰기(예: 풋스왑 → 크로스) | 2 | 핀치·사이드풀 |
| V7 | 2 | 옆·아래를 향한 홀드를 몸 위치로 버티기 | 2 | 언더클링·사이드풀·슬로퍼 |

- 문제 이름은 "무등산" 같은 실제 이름이 아닌 지어낸 이름(docs/44 사용자 지시).
- 홀드 간 거리: 적어도 홀드 크기만큼 떨어지게(docs/44, `hold_spacing.gd` 검사).
- 문제마다 설계 메모 한 단락: 주제, 핵심 구간(crux), 관문과 그 기술, 쉬는 자리. docs/41 등급 표, docs/43 V4~V7 설계를 따른다.
- 실금(`G_V8_01`): `grade`만 V4로 바꾸고 `route_id`는 그대로 둔다(저장된 기록이 이어지게, **[제안]**). 목록 순서(`order`)를 V4 자리로. 실금은 기술 관문이 없다(`required_techniques`·`crux_steps` 비어 있음). 어려움이 작은 홀드에서의 손 힘 관리에서 오므로 **관문 없는 V4**로 둔다 **[제안]** — V4 "기술 하나 필수" 주제의 예외로 적고, 새 V4 문제가 그 주제를 맡는다.

## 5.3 문제마다 검사 네 단계 (docs/48 §6 그대로)

1. R7 격자 검사: 관문에서 기술 없이 힘 해 없음.
2. 탐색기 기술 금지 → 길 없음(관문 있는 문제만).
3. 봇이 정답 순서(`intended_moves`)로 완등 → `score_ref`(작업 3) 기록, 최저 손 피로·한 발 구간 기록.
4. 사용자 플레이: 체감 등급 기록(APK). 체감이 어긋나면 배치를 고치고 1부터 다시.

검사 결과는 docs/41 등급 표 옆에 문제마다 한 줄로 남긴다.

## 5.4 해금 규칙 고치기

지금 해금은 "앞 등급에서 2개 완등"이고 문제가 없는 등급은 건너뛴다(`Progress.prerequisite_grade`). V2가 새로 생기면 V3의 앞 등급이 V1에서 V2로 바뀌어, **이미 V3를 하던 사람의 V3가 다시 잠긴다**. 규칙을 더한다: 그 등급 문제를 하나라도 완등한 적이 있으면 그 등급은 계속 열려 있다. 테스트로 확인.

## 5.5 등급 설명 문구

작업 3.6의 등급 설명 카드 문구를 실제로 만든 문제에 맞춰 고친다.

## 만드는 사람에게 맡기는 것

문제별 배치와 이름, 관문 기술 고르기(위 주제 안에서), 각 등급 문제 순서.

## 구현 기록 (2026-11-21, 0.9.59)

- §5.1 R7 도구: `GateCheck` + `tools/gate_check.gd`, 탐색기 기술 금지. 수업 6개 결과는 docs/48 §11.3. 하이스텝 수업은 몸통 끌기로 뚫림(재생 확인).
- §5.2 문제 11개 + 실금 V4: docs/41 §11 표. 생성기 `tools/routes/gen_routes.py`·`route_specs.py`.
- §5.3 검사: ① R7 ② 탐색기 ③ 봇 완등·score_ref는 모두 했다. ④ 사용자 체감은 아직.
- §5.4 해금: 그 등급을 하나라도 완등했으면 계속 열림(`Progress.grade_unlocked`, docs/28).
- §5.5 등급 설명 문구: `GradeInfo.TEXTS`를 실제 문제에 맞춤.
- AI 고스트 기록(`data/ai_ghosts`)도 새 문제마다 만들었다.

### 만든 사람 판단(확인 필요)

- 관문 문제는 기존 V3 뼈대를 뒤집고 홀드를 바꿔 만들었다 — 모양이 비슷한 문제가 많다. 비용: 사용자가 "같은 문제 같다"고 느끼면 새 뼈대로 다시 짜야 함(편집기 뒤가 쉬움).
- V6 예시(풋스왑 → 크로스) 대신 하이스텝 → 매치. 방향 홀드는 관문이 안 돼(R7) V7도 하이스텝·매치 관문 + 방향 홀드 재료. 비용: V7 주제("옆·아래 홀드를 몸으로 버티기")가 약하게 느껴질 수 있음.
- 등급은 봇 최저 손 힘을 docs/41 4장 표에 맞춰 매겼다(V4 54, V5 35~41, V6 25~28, V7 13~16). 비용: 체감과 다르면 홀드 크기로 다시 맞춤.
