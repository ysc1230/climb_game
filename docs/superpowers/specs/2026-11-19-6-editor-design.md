# 작업 6. 문제 만들기와 공유

2026-11-19 · 전체 순서는 [작업 1 문서 끝](2026-11-19-1-feel-design.md#작업-전체-순서). 표시: **[사용자]** / **[제안]**.

## 왜 하는가

클라이머에게 가장 오래 가는 재미는 직접 문제를 짜서 남에게 내는 것이다(docs/51 §3 C-13).

**[사용자]**

- 원하는 홀드를 원하는 위치에 놓는다. 오른쪽에 홀드 목록, 가운데에 세로 벽.
- 만든 문제는 모든 사람에게 공개해 별(추천)을 받거나, 특정 친구에게만 준다.
- 서버는 Supabase(무료판)로 해도 된다. 용량 걱정이 있었고, 계산해 보니 충분하다(아래 5).
- 모든 화면은 휴대폰 가로 기준.

## 목표 · 비목표 · 반목표

- 목표: 5분 안에 문제 하나를 만들어 직접 올라 보고, 공유 코드로 친구에게 보내거나 공개 목록에 올린다.
- 비목표: 댓글, 친구 목록, 온라인 랭킹, 관리자 화면, 벽 기울기(뒤로 미룸), 계정 가입(익명만).
- 반목표: 못 깨는 문제·홀드가 겹친 문제가 올라오는 것. 인터넷이 없을 때 게임 자체가 안 되는 것(만들기·내 문제 플레이는 인터넷 없이 돼야 함).

## 1. 들어가는 곳

홈 화면 탭에 [만들기]를 더한다(일반 · 기술 · **만들기** · 설정). 만들기 탭: [새 문제] · [내 문제](이 기기에 저장된 것) · [둘러보기](공개 목록) · [코드로 열기].

## 2. 만들기 화면 (시안: [캔버스 1번](https://claude.ai/artifact/Mr143fvFoggn2B7ETRzNWZ), 배치만 참고, 실제는 20:9 가로)

| 영역 | 내용 |
|---|---|
| 위 줄 | [나가기] · 문제 이름(최대 20자) · 예상 등급 고르기(V0~V7) · [되돌리기] · [직접 올라 보기] · [봇 검사] · [저장·공유] |
| 왼쪽 도구 | 놓기 · 옮기기 · 돌리기 · 지우기 · 시작 지정 · 탑 지정 |
| 가운데 | 세로 벽(폭 2.0m × 높이 4.5m **[제안]**), 위아래로 밀어 이동, 두 손가락으로 확대. 높이 눈금(m). 게임과 같은 3D 벽·홀드를 정면 카메라로 그린다(작업 4의 그림) |
| 오른쪽 목록 | 탭 [손홀드] [발홀드] [탑]. 종류 카드(작업 4의 8종류). 고른 홀드의 크기(S/M/L), 방향(0~355°, **5°씩 [사용자]**), 합손 켜기(손홀드) |
| 아래 상태 | 홀드 수, 높이, 검사 상태 |

- 놓기: 목록에서 종류를 고르고 벽을 누르면 놓인다. 위치는 1cm 단위로 자유.
- 돌리기: 홀드를 누른 채 두 손가락으로 돌리거나 오른쪽 방향 슬라이더. 5°씩 맞물림.
- 홀드 간 거리 규칙(docs/44, 적어도 홀드 크기만큼)을 어기면 그 홀드를 빨갛게 보이고 저장·공유를 막는다(`hold_spacing.gd`).
- 시작: 손 자리 2개와 발 자리 2개를 지정한다. **네 자리는 서로 다른 슬롯** **[제안]**(지금 `RouteDef._validate`가 시작 슬롯 중복을 오류로 막음 — 그대로 둔다).
- 시작 자세(골반 위치·각도): 지금 문제는 JSON에 손으로 적은 값이다. 만들기에서는 **새로 계산**한다: `PoseSolver.find_target`으로 네 시작 자리에서 가능한 골반 자세를 찾아 `start_pose`에 적는다. 못 찾으면 "시작 자세를 만들 수 없어요(손발이 너무 멀어요)".
- 탑: 탑 홀드 1개.
- 홀드 최대 40개 **[제안]**.
- 되돌리기: 최근 30단계.
- 색은 종류와 합손에 따라 자동(작업 4의 용도 색). 사용자가 색을 고르지 않는다.

## 3. 저장 · 검사 · 올리기

- 저장 형식은 일반 문제 JSON과 같다. `mode: "custom"` — 지금 `RouteDef.MODES`는 `general`·`course`뿐이라 **`custom`을 더해야 한다**. `name_ko`는 필수(문제 이름 칸). `route_id`는 기기에서 만든 고유값, 저장 위치 `user://my_routes/<route_id>.json`. 인터넷 없이 저장·플레이된다.
- 만든 사람의 완등 기록 `author_run`을 같이 저장한다(작업 3.8 — 점수 기준·시범 보기·힌트에 씀).
- [직접 올라 보기]: 지금 플레이 화면으로 그 문제를 연다(작업 1·3의 연출·점수 그대로). 끝나면 만들기 화면으로 돌아온다.
- [봇 검사]: 탐색기(`path_explorer.gd`)로 시작에서 탑까지 길이 있는지 본다. 결과: "깰 수 있어요" / "길을 못 찾았어요(가장 높이 간 곳 표시)".
- [봇 검사]는 **참고 정보**다 **[제안]**. 탐색기는 몸 끌기·다이노·균형 발·기술 버튼을 쓰지 않아서 사람이 깬 문제도 못 찾을 수 있다. 휴대폰에서 시간 상한 5초로 돌리고, 못 찾으면 "봇은 길을 못 찾았어요 — 직접 완등했다면 올릴 수 있어요".
- **올리기 조건** **[제안]**: ① 홀드 간 거리 규칙 통과 ② 시작·탑 지정 ③ 만든 사람이 도움 없이 직접 완등 한 번. 셋 다 되면 [저장·공유]에서 [친구에게 코드로] · [모두에게 공개]를 고를 수 있다. 실제 볼더링장에서 세터가 직접 올라 보고 여는 것과 같다.
- 올린 뒤 홀드를 고치면 새 판(`content_version` +1)이 되고 다시 올려야 한다. 이전 판의 별·기록은 유지하되 "고쳐졌어요" 표시.

## 4. 공유

- **친구에게 코드로**: 6글자 공유 코드(헷갈리는 0/O/1/I 빼고 `23456789ABCDEFGHJKLMNPQRSTUVWXYZ`). 화면에 코드와 [복사] 버튼. 받은 사람은 [코드로 열기]에 넣는다. 공개 목록에는 안 보인다.
- **모두에게 공개**: 공개 목록에 올라간다. 공개 문제도 공유 코드가 있다.
- **둘러보기**: 정렬 [별 많은 순] [최신] + 등급 거르기. 한 번에 20개씩. 카드: 이름, 등급, 만든 사람 별명, 별 수, 완등한 사람 수.
- **별**: 그 문제를 완등한 사람만 줄 수 있다(한 사람 한 번, 취소 가능) **[제안]** — 안 해 본 사람의 별을 막는다.
- **신고**: 문제 카드에 [신고]. 신고 3건이면 공개 목록에서 자동으로 숨김 **[제안]**. 이름에 거친 말이 있으면 올리기를 막는 간단한 낱말 목록.
- 별명: 처음에 "클라이머1234"처럼 자동, 설정에서 바꿈(최대 12자). 개인 정보는 받지 않는다.
- 공유 문제의 내 기록(점수·시간)은 이 기기에만 저장한다.

## 5. 서버 (Supabase)

**[사용자]** Supabase 무료판. **용량 계산**: 문제 하나 약 10KB(지금 문제 파일 4~8KB) → 500MB에 약 5만 개. 목록은 짧은 정보만 보내고 문제 전체는 플레이할 때만 받으므로 한 달 전송량 5GB로 약 50만 번 플레이. 가입자 한 달 5만 명 무료. 수치는 2026년 블로그 정리 기준이라 **만들 때 supabase.com/pricing에서 다시 확인한다.**

- 무료 프로젝트는 **1주일 동안 쓰임이 없으면 잠든다**. 저장소의 GitHub Actions 예약 작업으로 하루 한 번 목록 API를 불러 깨워 둔다. 게임은 "서버 연결 중… 다시 시도" 상태를 보여 주고 멈추지 않는다.
- 무료 프로젝트는 계정당 2개다. 2026-11-19 확인: 지금 `damnote` 하나만 있다(같은 조직). 작업 6을 시작할 때 같은 조직에 `climb_game` 프로젝트를 새로 만든다(서울 지역 `ap-northeast-2`). damnote와 섞지 않는다.
- 커지면 Pro(월 25달러, 잠들기 없음)로 올린다 — 사용자 결정.

**인증**: 익명 로그인(Supabase anonymous sign-in). 처음 만들기 탭 공유 기능을 쓸 때 자동으로. 토큰은 `user://`에 저장.

**표** **[제안]**

| 표 | 칸 |
|---|---|
| `routes` | `id uuid`, `code text unique`, `author uuid`, `author_name text`, `name text`, `grade text`, `data jsonb`(문제 JSON), `version int`, `visibility text`('public' / 'link'), `stars int`, `clears int`, `hidden bool`, `created_at`, `updated_at` |
| `stars` | `route_id`, `user_id`, 기본 키 둘 |
| `clears` | `route_id`, `user_id`, `version` (완등 기록 — 별 자격, 완등 수) |
| `reports` | `route_id`, `user_id`, `reason`, `created_at` |

- 행 단위 보안(RLS): 누구나 `visibility='public' and not hidden`을 읽고, 코드로는 하나를 읽는다(코드 조회 함수). 쓰기는 자기 `author`만. 별은 `clears`에 자기 기록이 있을 때만. `stars`·`clears` 수는 트리거로 센다.
- `data` 크기 제한(32KB 이하, check 제약). 한 사람 하루 올리기 20개(함수로 제한).
- 게임은 Godot `HTTPRequest`로 Supabase REST(PostgREST)·인증 API를 부른다. 공개 키(publishable key)만 앱에 넣는다. 비밀 키는 앱·저장소에 넣지 않는다(AGENTS.md).
- 표·정책은 마이그레이션 SQL 파일로 저장소에 남긴다(`server/supabase/migrations/`).

## 6. 문제 호환

- 공유 문제 JSON에 `schema` 판을 넣는다. 앱이 모르는 더 새 판이면 "앱을 업데이트해 주세요".
- 판정 판(`TUNING_VERSION`)이 바뀌면 공유 문제도 새 판정으로 플레이된다. 올리기 조건의 봇 검사는 올릴 때 판정 기준.

## 검증

- 헤드리스: 만들기 데이터 → `RouteDef` 읽기, 홀드 간 거리 검사, 시작 자세 만들기 실패, 5° 맞물림, 올리기 조건, 공유 코드 형식, 서버 응답 해석(가짜 응답).
- 서버: 정책 테스트(남의 문제 수정 불가, 완등 없이 별 불가, 숨김 문제 목록 제외).
- 기기: 사용자가 문제를 만들어 코드로 다른 기기에서 열기(APK 두 대 또는 같은 기기 재설치).

## 만드는 사람에게 맡기는 것

만들기 화면 세부 배치, 확대·이동 손동작 세부, 표 칸 이름, 거친 말 목록, 코드 만들기 위치(서버 함수 권장).

## 구현 기록

### 6A 만들기·내 문제 (2026-11-21, 0.9.60)

- `RouteDraft`(scripts/editor/route_draft.gd): 놓기(1cm)·옮기기·돌리기(5°)·크기·합손·지우기·시작 네 자리·탑 하나·되돌리기 30·홀드 40개. 막는 것 목록(이름·시작·탑·간격·시작 자세), 간격 위반 홀드, 올리기 조건, 문제 JSON(mode custom, schema 1).
- `MyRoutes`(scripts/editor/my_routes.gd): user://my_routes 저장·목록·읽기·지우기. `Game.edit`·`Game.play_custom`, [올라 보기] 뒤 만들기 화면으로 돌아옴.
- 화면: scenes/editor.tscn(EditorView = 플레이 장면의 벽·홀드 그리기를 물려받음 + EditorUI). 홈 [만들기] 탭.
- 탐색기에 시간 상한(5초), [봇 검사]는 스레드로 돌려 화면이 멈추지 않는다.
- 시험: test_route_draft(8), test_my_routes(3). 화면 확인 docs/images/editor.png.

만든 사람 판단:
- 시작 손은 손홀드만, 시작 발은 탑이 아닌 아무 홀드(발은 손홀드도 딛는다, docs/38).
- 시작 자세는 find_target + 시작에서 버티는지 봇으로 한 번 확인(넘어지면 "시작 자세를 만들 수 없어요").
- [봇 검사]의 "가장 높이 간 곳 표시"는 하지 않았다(탐색기가 높이를 모으지 않음). 결과 문구만.
- 두 손가락 돌리기 대신 돌리기 도구에서 가로로 끌기 + 버튼.
